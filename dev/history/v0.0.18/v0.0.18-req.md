### 2026-09-14 追加回答（A01〜A04）

- A04: Google／MicrosoftのSSOでサインインできる人は誰でもPHP版を利用できる。

### 2026-09-14 追加回答（A05・A06）

- A05: ブラウザー内の下書き自動復旧は残す。サーバー・原本への自動保存とは区別する。
- A06: 利用者が指定したパスワードでブラウザー内暗号化してから転送する。パスワードはサーバーに保存せず、再取得時に利用者が入力する。忘れた場合は復元不可とする。
- A07（追加質問）: さくらライトはcron非対応のため、10日で取得不可とし、アプリへのアクセス時に期限切れファイルを削除する案を確認中。アクセスがない期間も物理削除期限を守る必要があれば、外部から削除処理を定期的に呼ぶ仕組みが必要になる。

### 2026-09-14 追加回答（A07・保管期限の確定）

- A07: 10日で取得不可とし、アプリへのアクセス時に期限切れファイルを削除する。アクセスがない期間に暗号化ZIPがサーバーへ残ることを許容する。外部の定期削除処理は導入しない。

### メインツールバー

- Desktopは以前の並び順を基準とし、仕様変更済みのボタン増減は戻さない。
- Desktopの順序は「新規MD → 開く → 印刷 → HTML出力 → 診断 → 再読込 → 保存 → コード → プレビュー三択 → 分割方向 → 差分 → 外部で開く → フォルダー → VS Code → 別窓で開く → その他」。外部で開くは既存のラベルとして扱う。
- Webの主要操作は「開く → 印刷 → HTML出力 → 保存 → コード → プレビュー三択 → 分割方向 → 差分」の相対順序に揃える。「本文のみ保存」など条件付きの保存操作も維持する。
- Webの右端は、左から必ず「下書きを削除 → ファイル名 → オプション開閉」の順にする。先頭へファイル名を置く旧案は取り消す。
- Webのファイル名はダブルクリックで名前の変更に入る。
- Webのオプション開閉は1段目の右端に置き、狭幅時の折りたたみに用いる。下書きを削除はブラウザー内復旧データを明示的に消す操作として残す。
- 独立した「プレビュー」ラベルは削除する。コードのON/OFFトグルとプレビュー三択「OFF・プレビュー限定・ビジュアル編集」は維持する。
- 分割方向の選択肢は「自動分割・上下分割・左右分割」。本文レイアウトとは別の操作とする。
- 選択時の青は以前のDesktopの青に戻し、Webにも揃える。プレビュー限定とビジュアル編集の状態の違いは判別できるようにする。
- 削除済みの「画面」ラベルとコード側の重複する保存ボタンは復活させない。

### プレビューパネルのツールバー

| 項目 | Desktopの変更 | Web（HTML/PHP）の変更 |
|---|---|---|
| 上部1：見出し＋操作を選択 | メインツールバーから新設ツールバーへ移動 | 同じ場所に同等操作を設置 |
| 上部2：レイアウト | フッターから移動 | Desktopのコンボボックスを移植 |
| レイアウトの選択肢 | オート・A4縦・A3縦・プレゼン・画像中心を維持 | 同じ選択肢と表示機能を提供 |
| プレゼン単独ボタン | 設置しない | メインから削除し、レイアウトへ統合 |
| 左端の縦ツールバー：目次・検索・画像 | 既存の配置を基準とする | 目次・検索を左端へ移動し、画像の同等機能を追加。順序もDesktopに揃える |

検索入力は狭幅でもオプションメニュー内へ収納しない。目次を右上に置く旧案は左端の縦ツールバーへ変更する。

### Webの2段目の廃止とフッターの統一

Webの2段目は以下の移動後に廃止する。文字コードを左端に置き、文書情報を左側、表示設定と補助操作を右側に並べる。

| 項目 | Desktopの配置 | Web（HTML/PHP）の変更後 |
|---|---|---|
| 文字コード | フッター左端を維持 | 2段目からフッター左端へ移動。選択機能を維持 |
| BOM | 既存仕様を維持 | フッターの文字コードの隣へ移動 |
| サイズ・更新日時・変更状態など | 左側の状態表示を維持 | 対応する状態表示を配置し、重複表示はしない |
| テーマ | フッター右側1番 | フッター右側へ追加 |
| レイアウト | プレビュー上部へ移動 | フッターには設置しない |
| Auto Reload | フッター右側2番 | 非対応のため設置しない |
| Zoom | フッター右側3番 | ズーム倍率設定を追加 |
| 編集テスト結果 | フッター右側4番 | 設置しない |
| ショートカット一覧 | フッター右側5番 | 追加 |
| 設定 | フッター右側6番 | Webで利用できる設定項目を備えて追加 |
| ファイル名 | 既存のタブ表示を維持 | 1段目右端の「下書きを削除」と「オプション開閉」の間へ移動 |
| オプション開閉 | 既存仕様を維持 | 1段目の右端へ移動 |
| 下書きを削除 | 既存仕様を維持 | 1段目右端のファイル名の直前へ移動 |
| 重複するファイル名／文字コード表示 | ― | 削除 |

Webの右側操作欄は「テーマ → Zoom → ショートカット一覧 → 設定」の順とする。PHP固有のサインインや暗号化一時保管など、今回移動先を指定していない既存操作は維持する。

- [ ] **R17-03 プレビュー性能**：base64画像を多数含む文書では、画像のデコード・寸法取得・DOM描画を一括で行わず、表示領域に近いブロックから段階的に処理する。スクロール中の再計算と再描画を抑制する。100 KB未満の文書の通常表示を不必要に遅くしない。
- [ ] **R17-04 長いコードの既定折りたたみ**：drawio等の長いコードは、既存のコードブロック折りたたみ設定で定義されている行数を基準に既定で折りたたむ。新しい行数閾値を独自に追加しない。既存の設定値を変更する場合は別途要求として扱う。
- [ ] **R17-05 base64の既定折りたたみ**：base64画像は行数に関係なく、1行に収まる極端に長いデータも検出して既定で折りたたむ。テーブルの同一行にbase64画像が複数ある場合は、同じ折りたたみ操作で該当するすべてを折りたたむ。
- [ ] **R17-06 コード切替時の白画面**：コード表示へ切り替えた際、特定のデータを含む文書で画面が白くなる不具合を修正する。対象データを再現fixtureとして固定し、コード表示・プレビュー表示・モード切替の回帰テストに含める。例外は画面全体へ伝播させず、対象ブロック単位のエラー表示または安全なテキスト表示へフォールバックする。
- [ ] **R17-07 表示モード切替**：メインの表示切替として「コード」「コード｜ビジュアル」「ビジュアル」を提供する。別軸として「閲覧」「編集」を提供する。現在のレイアウト用途のview modeとは別の状態として管理する。
- [ ] **R17-08 モード切替の配置**：「コード」「コード｜ビジュアル」「ビジュアル」と「閲覧」「編集」は同じ行に配置し、2グループの間にセパレーターだけを置く。モードグループ間に改行を強制しない。操作領域はツールバー右側へ横並びで配置する。
- [ ] **R17-09 ツールバーの自然な折り返し**：既存のグループ単位のツールバー収納を維持しつつ、固定改行ではなく利用可能幅に応じて自然に折り返す。ボタンの重なり、文字欠け、グループ間の不自然な空白、操作の消失を起こさない。狭幅では既存の収納メニューを利用する。
- [ ] **R17-10 閲覧時の操作抑制**：閲覧モードでは「編集」等の変更操作を隠す。コードのコピー、表示切替、検索など閲覧に必要な操作は維持する。編集モードへ切り替えたときだけ編集操作を表示する。
- [ ] **R17-11 表UIの共通化**：通常Markdown表の列ソート、スライサー、検索、コピーを、既にTSV・CSVで動作している表UI・状態管理・表示順序と共通化する。通常表用に別仕様を作らず、形式差はデータ変換層で吸収する。
- [ ] **R17-12 表のソート**：列ソートは「未ソート → 昇順 → 降順 → 未ソート」の3段階トグルとする。複数列ソートを保持し、列ヘッダーにソート方向と優先順位を表示する。既存TSVの挙動を基準にする。
- [ ] **R17-13 スライサー候補検索**：各スライサーのフィルタ解除ボタンの隣にテキストボックスを置き、候補一覧を入力文字列で絞り込む。候補の選択状態とフィルタ解除の動作は既存TSVと一致させる。
- [ ] **R17-14 表のコピー統合**：表のコピーボタンを1つへ統合し、表全体・選択範囲・TSV・CSV・Markdown・プレーンテキスト等の候補はメニュー内へ配置する。既存のコピー経路を失わせない。
- [ ] **R17-15 表内画像**：表内の画像はセル幅を超えないように縮小し、画像のキャプションを画像の右側ではなく下側へ配置する。Markdown表、TSV/CSV由来の表、外部参照表で可能な範囲を揃える。
- [ ] **R17-16 ビジュアル編集のセル移動**：ビジュアル編集でテキストや画像を表セル内へ移動できるようにする。DOMだけを書き換えず、Markdownの行・セル境界を保った保存結果を生成する。
- [ ] **R17-17 埋め込み画像の外部化**：埋め込み画像を外部ファイルへ変換する途中でクラッシュしない。変換は一時ファイル、検証、Markdown反映の順で行い、失敗時は元の埋め込みデータを保持する。変換中は対象操作を無効化する。
- [ ] **R17-18 HTML出力完了通知**：「HTMLを出力しました」の通知に「フォルダを開く」「ファイルを開く」を追加する。出力先の検証と既存のファイルオープン経路を使用する。
- [ ] **R17-19 スクリプトなしHTMLの画像拡大**：スクリプトなし出力では、画像を元画像へのリンクとしてクリックできるようにする。ページ内モーダル、拡大縮小、閉じる等の高度なビューアはスクリプトあり出力で提供する。

### 追加要求の受入方針

- 100 KB境界、base64の1行長文、drawioの既存行数閾値、表内に2枚のbase64画像を置いたデータを固定fixtureとする。
- コード表示への切替で白画面にならないことを、対象fixtureの通常表示・コード表示・分割表示・閲覧／編集切替で確認する。
- 表UIはTSVの既存テストを基準に、通常Markdown表へ同じソート・解除・多段ソート・候補検索・コピー仕様を適用する。
- 本追加要求では製品コード、生成物、公開サイトを変更しない。実装開始時に対象版の実装計画と進捗を更新する。
