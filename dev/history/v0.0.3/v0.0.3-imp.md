## 0. 事前確認（ユーザー回答・実測結果）

### 0-1. 確定仕様

| 論点 | 決定 |
| :--- | :--- |
| 外部操作 | 初期の直接ボタンはフォルダー／VS Code。「その他」の初期項目はメモ帳。設定で配置を変更可能 |
| 外部アプリ引数 | 実行ファイルと引数配列を分離し、`${file}`／`${dir}`／`${line}`だけ置換 |
| 設定画面 | ステータスバー右端の歯車から、単一の設定専用タブを開く |
| 子見出し分割 | 直下の子が1つかつ10ソース行以内だけ親へ併合。それ以外は小見出しリスト |
| パンくず | 階層数無制限、1行横スクロール、現在階層へ自動追従 |
| アンカー一致 | fold-id、テキスト指紋、近接位置を用いる決定的な方式を実装者が選定 |
| プレゼン画像 | 初回クリックで全画面ポップアップ、ホイール拡縮、Esc終了。再クリックでローカルラスターのみ既存編集へ移る |

### 0-2. テーマ不具合の切り分け

`themes.css` にはテーマ別変数があるが、添付実画面ではライト系でも表見出しとインラインコードが
ダーク系と同じ背景になっている。宣言値の単体確認では不十分だったため、実装ではWebView上の
`getComputedStyle` とスクリーンショットを受入証拠にする。テーマ切替直後、設定読込後、
プレゼン表示の3経路を検証する。

## 2. 要件別・実装方針

### 2-1. テーマ配色

テーマごとに表見出し、インラインコード、コードブロックの背景・文字色を明示的な変数へ分離する。
テーマ属性の適用先とCSS import順を検証し、テスト用DOMの計算済みスタイルを取得する。
ライト／GitHubはVS Code・GitHub系の低彩度ライト背景、ダーク系は本文より一段明るい背景を使う。

### 2-2. 意味的スクロールアンカー

Markdownのブロックへソース位置、最寄り見出しID、正規化テキスト指紋を付ける。
reload直前に画面上端へ最も近い可視ブロックとブロック内pixel offsetを保存する。
再描画後、次の優先順位で復元する。

1. 同じstable block ID
2. 同じ見出し配下でテキスト指紋が一致する最寄りブロック
3. 同じ見出し
4. 直前に存在したブロック
5. 文書全体のscroll比率

fold状態適用後、2回のanimation frameを経てレイアウトが安定してから復元する。

### 2-3. 設定スキーマ・安全な外部アプリ起動

設定にschema versionと `externalApps[]` を追加する。要素は `id`、`label`、`executable`、
`args[]`、`workingDirectory`、`enabled`、`placement`、`order`、`builtinKind` を持つ。
Rustはシェルを介さず `Command` へ引数を個別追加し、許可プレースホルダーだけを置換する。
既存設定は初回読込時にフォルダー／VS Code／メモ帳の既定構成へ移行する。

### 2-4. 設定専用タブ

ファイルタブと設定タブを判別できるunion stateへ拡張する。設定タブはsingleton IDとし、
歯車操作では既存タブを再利用する。編集内容はローカルdraftに保持し、保存成功後にアプリ全体へ反映する。

### 2-5. 外部操作UI

`placement=primary` の有効項目を直接ボタン、`placement=menu` を「その他」へ表示する。
組み込みフォルダーは削除不可、他の項目は設定画面で編集可能とする。メニューは外側クリック、
フォーカス移動、Esc、実行後に必ず閉じる。

### 2-6. プレゼンモデル

Markdown ASTから見出しツリーと各見出し直下のソース行数を算出する。直下の子が1つかつ
10行以内だけ親ページへ併合し、複数または超過時はナビゲーションページを作る。
見出しなし文書には仮想root、飛び級には内部仮想階層を使い、表示パンくずには実見出しだけを出す。

### 2-7. プレゼンUI

プレゼン専用コンポーネントで現在ページだけをDOMへ描画する。パンくずはnowrap＋horizontal scroll、
末尾要素を `scrollIntoView({inline:"end"})` で追従させる。左右キーは入力欄、モーダル、
ページ内の横スクロール操作中には奪わない。

### 2-8. プレゼン画像

`object-fit: contain` と利用可能viewport高で初期fitする。ポップアップはウィンドウ内fixed layerとし、
倍率・原点を状態管理する。ホイールは段階拡縮し、1倍未満へ縮小しない。再クリック時、
ローカルラスターならポップアップを閉じて既存crop targetを開始する。SVG等には編集カーソルを出さない。

## 6. 検証計画

### 6-1. 自動

* 全テーマの計算済み表見出し・インラインコード背景色と文字色
* reload前位置より前への追加／削除、同文重複、アンカー削除、fold状態
* 外部アプリの移行・CRUD・並び順・配置・プレースホルダー・危険文字
* 設定タブsingleton、draft保持、保存失敗
* H1〜H6、飛び級、同名、見出しなし、子0/1/複数、9/10/11行
* パンくず移動、前後移動、通常表示復帰、キー競合
* PNG/JPEG/GIF/WebP/SVG/data/外部画像のfit・popup・編集可否

### 6-2. 実機

* release EXEで各テーマを切り替え、スクリーンショットと計算済み色を保存する
* 設定専用タブでアプリ配置を変更し、再起動後も保持されることを確認する
* 深い見出し・長文・画像中心の資料をプレゼンし、スクロール量と操作性を確認する
* GUI自動操作は起動後5秒間入力を監視し、人間入力を検知したら承認待ちにする
