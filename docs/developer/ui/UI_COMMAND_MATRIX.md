# UI機能対応表

正本は `config/ui-command-contract.json`。`npm run check:ui-contract` が未登録・削除・名称/順序/属性変更・CSS変更とこの表の更新漏れを検出する。表はソース上の対応を示し、非表示条件・実寸・実操作の合格を推測しない。

## 共通の操作規約

| ID | 表示名 | 許容する状態表示 | 相対順序 |
| --- | --- | --- | --- |
| document.print | 印刷 |  | 10 |
| document.export-html | HTML出力 |  | 20 |
| document.save | 保存 | 保存中… / ZIPを保存 | 30 |
| document.diff | 差分 |  | 40 |

書式操作は `editorToolbarActions.ts` の単一リストをDesktop/HTML/PHP/SPFxで使用する。表示切替は共通部品とCSSを使用する。デスクトップの新規/再読込、Webの開く/ZIP、PHPの一時保管など固有操作は共通コマンドの相対順を崩さず配置する。

## 全操作の登録

登録 1114 件。動的表示の展開、条件付き表示、キーボード到達、画面の高さは実画面で別途確認する。「別実装/未対応」は利用不可の承認や合格を意味しない。

番号は同じ操作領域内で1から付ける。UIxxxがツールバー/メニューの識別番号、末尾が項目順。子メニューは別領域とし、動的生成など実表示順を確定できない箇所は定義順と明記する。既存のui-IDは変更しない。

[全操作の登録表（TSV）](/docs/developer/ui/UI_COMMAND_MATRIX.tsv)を開いてください。UTF-8、ヘッダー付き、タブ区切りです。

## デザインの静的検査

操作UIに関するCSS 343 規則を登録。値変更はレビューが必要。既存のCSS分布レポートは用途別の少数値を示すが、少数値だけで不具合とは判定しない。共有CSSでもホスト側のカスケード差は実寸検査が必要。
