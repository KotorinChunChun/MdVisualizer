# 爆速 Markdown Viewer v0.0.5 要求定義書

作成日: 2026-08-02
ステータス: **機能改良案・レビュー待ち**

## 1. 目的

v0.0.4までに整備したタブ、目次、プレゼン、履歴、画像編集を土台として、
複数のMarkdownを日常的に閲覧する流れを改善する。

v0.0.5では、文書内の必要箇所を素早く見つけ、文書内の問題を確認し、
通常表示とプレゼン表示に適した形式で印刷またはPDFとして共有できる状態を目指す。
あわせて、本文上のマウスポインター位置と目次の現在位置表示を直感的に連動させる。
さらに、ウィンドウ配置、VS Code連携、表示倍率、ツールバー操作を改善し、
複数の文書やウィンドウを扱う際の操作負担を減らす。

## 2. 設計方針

* 既存のタブ、目次、戻る・進む、検索、外部アプリ連携を再利用する
* マウスだけでなくキーボードでも主要操作を完結できるようにする

## 3. 過去版からの継承と整理

本要求は `v0.0.1-req.md` から `v0.0.4-req.md`、各実装計画・検証報告、
`実装するかも.md` を通して確認した未完了事項と将来候補を基にする。

### 3.1 維持する中核

* v0.0.3以降の意味的スクロールアンカー、プレゼン、戻る・進むを新しい移動経路でも利用する

### 3.2 v0.0.5へ引き継ぐ候補

過去文書で将来候補または残件として挙げられ、現在も未実装の次項目を採用する。

* PDF出力。既存の印刷風レイアウトとOS印刷を利用する
* 検索結果を前後行付きで一覧表示する検索拡張
* プレゼンモードでも利用できる文書検索

### 3.3 今回採用しない将来候補

次項目は独立した設計・安全性評価または実測が必要なため、v0.0.5へ含めない。

* SVGベクタ編集、画像回転
* PlantUML、KaTeX、Excalidraw
* カスタムテーマ作成、ショートカット割り当て変更
* タブをウィンドウ外へドラッグして分離する操作
* ポータブル版
* 仮想スクロール。既存方針どおり、性能実測で必要性を確認してから判断する

### 3.4 着手前提

* v0.0.4追加要件のショートカット一覧、プレゼン履歴安定化を受入済みにする
* v0.0.3／v0.0.4で保留されたGUI確認は、各版の回帰確認としてv0.0.5着手前または統合検証時に完了する
* GUI確認ではリポジトリ規則に従い、起動後5秒間の入力監視と、人間入力検知時の安全な中止を行う
* v0.0.5で既存機能の不具合が判明した場合は、機能追加と混在させず回帰修正として先に解消する

## 4. 必須機能

### 4.1 検索結果パネル

* 既存の文字列、大小文字、正規表現の検索条件をそのまま利用する
* 検索ボタンを押したときに表示する検索入力ボックスは、検索ボタンのすぐ隣に配置する
* 検索結果が複数ある場合は、画面左側に検索結果一覧を表示する
* 検索結果一覧は目次パネルと同様のUIで表示する
* 一致箇所は検索語を含む行を必ず表示し、設定された前後の文脈行も併せて表示する
* 文脈行数は0～5行で変更でき、既定値は2行とする
* 結果には行番号、見出し階層、該当文字列のハイライトを表示する
* 結果をクリックまたはEnterで選択すると、折りたたまれた親を展開して本文位置へ移動する
* 検索結果からの移動を既存の戻る・進む履歴へ記録する
* 入力中は短時間のdebounceを行い、大きな文書で連続再計算しない
* 結果が500件を超える場合は先頭500件まで表示し、打ち切ったことを明示する
* 不正な正規表現は結果を消すだけにせず、入力欄付近へ理由を表示する
* 通常表示とプレゼン表示で同じ検索モデルを利用し、プレゼンでは該当見出しページへ移動して一致箇所を示す
* プレゼンから検索結果へ移動しても、左右キーによるページ移動と検索UIのキー操作を競合させない

### 4.2 文書診断

* 現在文書に含まれるローカルMarkdownリンク、見出しアンカー、画像参照を検査する
* 存在しない文書、画像、参照先見出しをエラーとして一覧表示する
* 同一文書内で衝突する見出しIDや、空の画像altを警告として表示する
* 診断結果は重要度、種別、行番号、参照文字列を含む
* 診断項目から該当する本文位置へ移動し、既存の戻る・進む履歴へ記録する
* 文書または参照先ファイルの変更を検知した場合は診断結果を更新する
* 診断エラーがあっても文書表示、印刷、外部アプリで開く操作を禁止しない

### 4.3 印刷とPDF出力

* 既存の「印刷」表示モードを印刷プレビューとして再利用し、`Ctrl+P` からOSの印刷ダイアログを開ける
* 印刷時はタブ、ヘッダー、ステータスバー、サイドバー、操作ボタンを出力しない
* 印刷およびPDF出力には目次を含めない
* ライト配色の印刷用スタイルを使用し、選択中のアプリテーマへ依存しない
* 通常レイアウトとプレゼンレイアウトで別の印刷フォーマットを使用する
* 通常レイアウトでは文書を連続したページとして出力する
* プレゼンレイアウトでは1スライドを1ページとして扱い、各スライドの末尾へ強制改ページを入れる
* プレゼンレイアウトではパンくず、前へ／次へボタン、ページ操作UIを出力しない
* 見出し直後の本文、表、コードブロック、画像を可能な限り不自然な位置で分割しない
* Mermaidの描画完了またはエラー確定を待ってから印刷を開始する
* 折りたたまれた見出しは、印刷時だけ一時的に展開する選択肢を用意する
* 文書タイトル、元ファイル名、印刷日時、ページ番号の表示有無を設定できる
* Windowsの「Microsoft Print to PDF」を利用したPDF保存を正式な利用手順として案内する
* 印刷後は画面上の折りたたみ、スクロール、表示モードを元の状態へ戻す

### 4.4 目次の現在位置表示

* 目次で点灯する現在位置は、本文上のマウスポインター位置を基準に決定する
* 本文上のポインター位置に対応する見出し区間を求め、その見出しを目次で点灯する
* スクロールイベントだけでは目次の点灯位置を変更しない
* ポインター移動は適切に間引き、本文操作やスクロールを妨げない
* ポインターが本文外へ出た場合は、最後に確定した目次項目の点灯を維持する
* 目次項目をクリックした直後は移動先を点灯し、その後本文上でポインターが動いた時点でポインター基準へ戻す

### 4.5 標準レイアウトの目次ボタン

* プレゼンレイアウトで表示している目次ボタンを標準レイアウトでも表示する
* ボタンの配置、外観、目次パネルの開閉方法は既存の目次ボタン仕様に合わせる
* 標準レイアウトとプレゼンレイアウトで同じ目次モデルを利用する

### 4.6 ウィンドウ位置・サイズと複数ウィンドウ

* アプリ終了時にウィンドウの位置とサイズを保存する
* 次回起動時は保存した位置とサイズでウィンドウを表示する
* アプリ起動中に別のMarkdownファイルを開いた場合は、既存ウィンドウと重ならない位置へ新しいウィンドウを表示する
* 新しいウィンドウは既存ウィンドウと同じサイズで表示する
* 新しいウィンドウの配置は既存ウィンドウの真右を優先する
* 真右では画面外にはみ出す場合、既存ウィンドウの真左へ配置する
* 「外部で開く」ボタン群に「別窓で開く」を追加する
* 「別窓で開く」を実行すると、現在と同じMarkdownファイルを本アプリの新しいウィンドウで開く
* 新しいウィンドウは既存ウィンドウとは独立して操作、移動、サイズ変更、終了できる

### 4.7 VS Code連携

* 「VS Codeで開く」では、起動中の全VS Codeワークスペースを確認し、対象Markdownファイルを配下に含むワークスペースがある場合はそのウィンドウ内で対象ファイルを開く
* 複数の起動中ワークスペースが対象ファイルを含む場合は、対象ファイルに最も近い、最も深い階層のワークスペースを優先する
* マルチルートの`.code-workspace`は、定義された各`folders`のいずれかが対象ファイルを含む場合に同じワークスペースとみなす
* 対象ファイルを含む起動中ワークスペースがない場合は、対象ファイルの親から上位フォルダを再帰的に探索してワークスペースを推定する
* 推定時は、対象ファイルを含む`.code-workspace`、`.git`、`.vscode`、主要なプロジェクト定義ファイル、`.claude`または`AGENTS.md`の順に候補を選ぶ
* `.claude`と`AGENTS.md`は補助候補とし、ユーザーホームをワークスペースとして誤選択しない
* 推定候補がない場合は、対象Markdownファイルが存在するフォルダをワークスペースとする
* 同じワークスペースを開いているVS Codeウィンドウが存在しない場合は、推定したワークスペースを新しいVS Codeウィンドウで開いた後、対象Markdownファイルを開く

### 4.8 表示倍率

* `Ctrl` キーを押しながらプレビュー画面上でマウスホイールを操作すると、プレビュー画面全体の表示倍率を変更できる
* 表示倍率は1回の操作につき10%単位で拡大または縮小する

### 4.9 「その他」メニュー

* 「その他」メニューはツールバー内へ展開せず、独立したポップアップメニューとして表示する
* 「その他」メニューの開閉によってツールバーの高さを変化させない

### 4.10 Obsidian画像埋め込み

* Obsidianで使われる`![[画像ファイル]]`および`[[画像ファイル]]`をプレビュー上の画像として表示する
* Wikiリンクの対象が画像拡張子を持つ場合だけ画像として扱い、通常のノートリンクやコード内の記法は変換しない
* `[[画像ファイル|代替テキスト]]`の代替テキストを画像altおよび表示キャプションとして利用する
* Obsidian画像を画像一覧とファイル監視の対象に含め、画像ファイル更新時にプレビューへ反映する
* 画像altの表示キャプションは画像本体の下へ配置し、画像リサイズ枠や下罫線と重ならないようにする

### 4.11 機能確認サンプルとバージョン情報

* `samples`へ最近追加した検索、目次、倍率、別窓、VS Code連携、Obsidian画像、alt配置を確認できるMarkdownファイルを追加する
* `？`ボタンで開くページ下部へバージョン情報欄を表示する
* バージョン情報欄には更新日、バージョン、作者名、GitHub READMEリンク、GitHubリリースリンクを表示する
* GitHubリンクは既存の安全な外部URL起動経路を使ってブラウザーで開く

### 4.12 MSIXインストーラー

* Windows 10 2004以降のx64環境へ導入できるMSIXパッケージを生成する
* MSIXにはリリース版実行ファイル、アプリアイコン、`.md`／`.markdown`のファイル関連付けを含める
* パッケージのバージョンはアプリのバージョンから4要素のMSIXバージョンへ変換する
* 開発時は自己署名証明書で署名済みMSIXと公開証明書を生成し、秘密鍵を成果物へ残さない
* 本番配布時は外部のコード署名PFXとタイムスタンプサービスへ差し替えられるようにする
* 開発用証明書を明示的に信頼した場合だけ、現在のWindowsユーザーへ導入する補助スクリプトを提供する
* Publisherは署名証明書のSubjectと一致させ、更新可能なIdentityを維持する

## 5. アクセシビリティ要件

* 検索結果、診断一覧、印刷操作、目次、「その他」メニューをキーボードだけで操作できる
* ドロワーとモーダルはフォーカスを内部へ保持し、閉じた後は起点へ戻す
* 現在選択中、警告、エラーを色だけで区別しない
* `prefers-reduced-motion` が有効な環境では不要なアニメーションを抑制する

## 6. 対象外

v0.0.5では次を実装しない。
本プロジェクトで永久的に対象外とする項目は [`reject.md`](../reject.md) に記録する。

* SVGのベクタ編集、PlantUML、KaTeX、Excalidraw
* ショートカット割り当て変更とカスタムテーマ作成
* タブのウィンドウ外ドラッグ分離

## 7. 受入基準

* 検索結果一覧から折りたたみ内の一致箇所へ移動し、戻る操作で元の位置へ戻れる
* 検索入力ボックスが検索ボタンのすぐ隣に表示され、複数の検索結果が目次と同様の左側パネルへ表示される
* プレゼン表示でも検索結果から該当ページへ移動し、検索UIとページ送りのキー操作が競合しない
* 存在しないMarkdownリンク、見出しアンカー、画像を正しい行番号で検出できる
* ダークテーマ利用中でも、印刷結果は読みやすいライト配色になる
* 通常レイアウトの印刷・PDFでは本文を連続ページとして出力し、目次を含めない
* プレゼンレイアウトの印刷・PDFでは1スライドごとに改ページし、目次・パンくず・ページ操作UIを含めない
* Mermaid、表、コード、画像を含む通常レイアウトとプレゼンレイアウトの両方をMicrosoft Print to PDFで保存できる
* 本文上でマウスポインターを異なる見出し区間へ移動すると、対応する目次項目の点灯が変わる
* マウスポインターを動かさずにスクロールしただけでは、目次の点灯位置が変わらない
* 標準レイアウトでも既存仕様と同じ配置と操作方法の目次ボタンを利用できる
* アプリを終了して再起動すると、保存したウィンドウ位置とサイズが復元される
* 複数ウィンドウは既存ウィンドウと同じサイズで、画面内の真右または真左へ重ならずに表示される
* 「別窓で開く」で同じMarkdownファイルを開き、各ウィンドウを独立して操作できる
* 「VS Codeで開く」で対象ファイルを含む既存VS Codeワークスペースが再利用され、存在しない場合だけ推定した上位ワークスペースを新しいウィンドウで開く
* `Ctrl` とマウスホイールの操作ごとに、プレビュー画面全体の表示倍率が10%ずつ変化する
* 「その他」メニューを開閉してもツールバーの高さが変化しない
* Obsidian画像埋め込みが表示され、代替テキストが画像下の罫線と重ならない
* 最近追加した機能を`samples`内の専用ファイルで確認でき、`？`ページ下部からバージョン情報とGitHubリンクを確認できる
* 署名済みMSIXを生成でき、展開後のマニフェスト、実行ファイル、アイコン、Markdown関連付けを確認できる
* 検索、診断、印刷、目次、「その他」メニューはマウスを使わずに操作を完了できる

## 8. 検証計画

* 通常／プレゼンそれぞれの検索0件、1件、複数件、500件、501件、不正な正規表現、折りたたみ内ジャンプ
* 検索ボタンと入力ボックスの隣接表示、複数結果時の左側パネル、目次パネルとのUI整合性
* 相対／絶対Markdownリンク、URLエンコード、重複見出し、欠落画像、空altの診断
* 通常レイアウトで、目次非表示、連続ページ、折りたたみ展開、ライト配色を確認する印刷テスト
* プレゼンレイアウトで、目次・パンくず・操作UI非表示、スライド単位の強制改ページを確認する印刷テスト
* Mermaid描画成功・失敗・タイムアウト、長い表、コード、画像を含む両レイアウトのPDF保存
* 印刷前後で折りたたみ、スクロール、表示モードが変化しないことの回帰テスト
* 本文の各見出し区間へポインターを移動し、対応する目次項目だけが点灯することのGUIテスト
* ポインター静止中のスクロール、本文外への退出、目次クリック直後、再度の本文ポインター移動を含む点灯状態テスト
* 標準／プレゼン両レイアウトで目次ボタンの配置、表示、開閉を確認する回帰テスト
* 通常終了後の位置・サイズ復元と、異なる画面端条件で真右／真左へ配置する複数ウィンドウテスト
* 「別窓で開く」で同一ファイルを複数表示し、一方の操作や終了が他方へ影響しないことのテスト
* 対象ファイルを含む上位フォルダまたはマルチルートワークスペースを開いたVS Codeが存在する場合と存在しない場合の「VS Codeで開く」連携テスト
* `Ctrl` とホイールによる10%単位の拡大・縮小、およびプレビュー全体への反映を確認するテスト
* 「その他」メニューの表示位置、キーボード操作、開閉前後のツールバー高さを確認するテスト
* Obsidian画像埋め込み、通常Wikiリンクの非変換、画像一覧・監視対象への追加、キャプションとリサイズ枠の分離を確認するテスト
* サンプル内リンク・画像参照の存在確認と、バージョン情報の全項目・外部リンク操作を確認するcomponent test
* MSIXを生成して署名者、パッケージ内容、4要素バージョン、x64アーキテクチャ、`.md`／`.markdown`関連付けを検証する
* GUI自動操作を行う場合は、アプリ表示後5秒間の入力監視と人間操作検知時の中止を必須とする

## 9. 提案時の既定値とレビュー項目

以下は実装前に確定する。現時点の推奨値を併記する。

| # | 論点 | 推奨する既定値 |
| :--- | :--- | :--- |
| 1 | 検索の文脈行数 | 前後2行、最大500件 |
| 2 | 印刷時の折りたたみ | 既定ですべて展開し、設定で現在状態も選択可能 |
| 3 | PDF出力 | OS印刷機能を利用する |
| 4 | 通常レイアウトの印刷 | 連続ページ、目次なし |
| 5 | プレゼンレイアウトの印刷 | 1スライド1ページ、目次・パンくず・操作UIなし |
| 6 | プレゼン検索 | 通常検索と同じ条件・結果モデルを共有 |
| 7 | 目次の点灯 | 本文上のポインター位置を基準とし、スクロールだけでは変更しない |
| 8 | 複数ウィンドウの配置 | 既存ウィンドウの真右を優先し、画面外になる場合は真左 |
| 9 | 表示倍率の変更幅 | 1操作につき10% |

## 10. 実装優先順位案

| 優先度 | 機能 | 理由 |
| :--- | :--- | :--- |
| P0 | 検索結果パネル | 既存検索を大規模文書でも実用的にする |
| P0 | ウィンドウ管理と別窓表示 | 複数文書・複数ウィンドウの基本操作を安定させる |
| P0 | 印刷とPDF出力 | 通常／プレゼンの共有形式を確立する |
| P0 | 目次のポインター連動 | 現在位置表示を利用者の注視位置へ合わせる |
