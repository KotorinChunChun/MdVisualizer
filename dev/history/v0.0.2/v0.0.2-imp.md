## 0. 事前確認（ユーザー回答・現状分析）

### 0-1. 実装前に確認した仕様

| #   | 論点                       | 決定                                       | 選定理由・技術的背景                                                                                                                                                                                                                                   |
| :-- | :------------------------- | :----------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | バージョンとリリース単位   | v0.0.2 として一括実装                      | v0.0.1 は `release/Publish/MarkdownViewer_.zip` として配布済み。同じ版番号で中身を差し替えると配布物と対応が取れなくなるため版を上げる。要求書のファイル名は `v0.0.2-req.md` のまま据え置く |
| 2   | 多重起動の挙動             | 毎回新プロセス                             | `tauri-plugin-single-instance` を導入しない。引数転送・プロセス間通信が不要になり、`lib.rs` の起動シーケンスを現状のまま維持できる。起動性能（要求19.1: 300ms以下）にも有利                                                                            |
| 3   | 永続化範囲                 | 設定＋ファイル単位の折りたたみ状態         | `settings.json` / `fold-state.json` に `schemaVersion` を持たせる。保存時はOS排他ロック取得後に最新内容を再読込し、変更キーをマージして「一意な一時ファイル→flush→rename」で原子置換する。単純なlast-writer-winsは採用しない |
| 4   | セッション（タブ一覧）復元 | 行わない                                   | #2 で毎回新プロセスとなるため、復元すると `.md` をダブルクリックするたびに前回のタブが増殖する。要求19.4のタブ復元は未実装として残し、`§7 残件` に明記する                                                                                             |
| 5   | タブのウィンドウ分離       | 並び替えまで実装、分離は右クリックメニュー | ウィンドウ外へのドラッグ分離は、WebView内のdragendではドロップ先座標しか取れず、新ウィンドウ生成とマウスキャプチャの引き継ぎをRust側で自作する必要がある。この1項目だけで他フェーズ相当の工数になるため将来拡張へ                                      |
| 6   | シンタックスハイライト     | highlight.js を遅延ロード                  | `highlight.js/lib/core` ＋主要言語のみ登録で gzip 30KB前後。Shiki はWASM＋TextMate文法で数MB規模になり、要求19.1（起動300ms）と19.2（メモリ100MB）に対して割に合わない                                                                                 |
| 7   | 大規模Markdown             | 全件描画＋実測                             | 仮想スクロールは Ctrl+F のブラウザ標準検索、テキスト選択、折りたたみ、スクロール位置復元のすべてと衝突する。まず `content-visibility: auto` による描画スキップで実装し、1万行サンプルで実測して判断する                                                |
| 8   | 検証粒度                   | フェーズ完了ごとに実機起動                 | 各コミット前に `tsc` / `npm run build` / `cargo test` を通し、フェーズ区切りで `dev/scripts/run-test.ps1` を実行してスクリーンショットを撮る |
| 9   | 複数ウィンドウ監視         | ウィンドウ別所有＋Rust側全体和集合         | `HashMap<WindowLabel, HashSet<PathBuf>>` を保持し、各ウィンドウの更新で他ウィンドウの監視対象を消さない。実watch/unwatchは全体和集合との差分だけ行う |
| 10  | 非アクティブタブ           | 本文DOMをアンマウント                      | タブ状態はReducerへ保存し、本文DOM・検索Range・Mermaid SVGはアクティブタブだけ保持する。10,000行×複数タブでのメモリ増加を抑える |
| 11  | Markdown内HTML             | `rehypeRaw` → fold → sanitize               | 生HTMLをノード化した後、折りたたみ構造を付与し、最後に許可リストでサニタイズする。危険URL、イベント属性、任意styleを許可しない |
| 12  | ページ内検索               | Custom Highlight優先＋安全なfallback       | Highlight名をウィンドウ・タブ単位で分離し、終了時に削除する。非対応時だけ所有権付き`mark`要素を使用し、再描画前に必ず除去する |
| 13  | Mermaidテーマ              | 初期化は一度、図単位frontmatterへ反映      | 安全設定を一度だけ初期化し、アプリテーマを元コードとは別の一時frontmatterへマージして描画する。元ファイルは変更しない |
| 14  | タブバー右端の `+`         | v0.0.2では表示しない                       | ファイルを開くメニューを持たない要求5.4と衝突するため。別ウィンドウ化は右クリックメニューに一本化する |

### 0-2. 現状（v0.0.1）の実装分析

v0.0.2版へ拡張するうえで、**現状のどこが単一ファイル前提になっているか**を先に洗い出した。

| 箇所                                  | 現状                                                                                         | v0.0.2版での問題                                                                                      |
| :------------------------------------ | :------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------- |
| `src/App.tsx`                         | `useMarkdownFile` を1回呼び、単一の `filePath` / `markdownData` を保持                       | タブ＝複数ドキュメントを同時に保持できない                                                            |
| `src/hooks/useMarkdownFile.ts:5`      | フック内部で「初期ファイル取得 → 読み込み → 監視開始 → F5リスナー登録」を全部やる            | タブごとにインスタンス化するとF5リスナーがタブ数だけ多重登録される                                    |

| `src-tauri/src/commands.rs:26`        | `start_watch` が呼ばれるたびに監視対象を**全置換**（`set_watch_targets` が既存を全 unwatch） | タブAを開いた後にタブBを開くとAの監視が外れる                                                         |
| `src-tauri/src/markdown.rs:22`        | `fs::read_to_string` = UTF-8 固定                                                            | 要求17.2「文字コード」をステータスバーに出せない。Shift_JIS / UTF-16 のファイルは読み込みエラーになる |
| `src/components/MarkdownPreview.tsx`  | `ReactMarkdown` に `img` レンダラだけ差し込む                                                | 折りたたみ・コードブロック・Mermaid・リンク処理の差し込み口が無い                                     |
| `src-tauri/src/lib.rs:15`             | 起動引数から `.md`/`.markdown` を**1つだけ**拾う                                             | 複数ファイルを引数で渡された場合に1つしか開けない                                                     |
| `src-tauri/capabilities/default.json` | `"windows": ["main"]` 固定                                                                   | 別ウィンドウを開くと権限が付与されずコマンド呼び出しが全部失敗する                                    |
| 設定・折りたたみ状態（新規）          | 複数プロセスから同じJSONへ書き込む予定                                                  | 原子置換だけでは別プロセスの更新キーを消すため、排他後の再読込・マージが必要                           |
| 検索Highlight（新規）                 | `CSS.highlights` はドキュメント単位の名前付きレジストリ                                  | タブ共通名を使うと検索結果が上書きされる。タブID付きの名前とcleanupが必要                              |
| 非同期読込・Mermaid（新規）           | タブ切替・連続保存中に処理完了順が逆転し得る                                              | 世代番号なしでは古い結果が最新表示を上書きする                                                         |

→ **P0で技術成立性を確認し、P1でこれらの基盤を作り替える。** ここを飛ばして機能を足すと後段で作り直しになる。

## 2. 要件別・実装方針

### 2-1. タブ機能（req 4.1〜4.4）

| 項目                   | 内容                                                                                                                                                                                                                                     |
| :--------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実装箇所               | 新規 `src/state/tabsReducer.ts`, `src/components/TabBar.tsx`, `src/components/DocumentView.tsx` / 既存 [App.tsx](../../../src/App.tsx) を全面改修                                                                                                   |
| 方式                   | タブ集合を `useReducer` で管理する。1タブ = `{ id, path, doc, scrollTop, foldState, search, status, loadGeneration }`。**本文DOMはアクティブタブだけマウント**し、切替前にスクロール・折りたたみ・検索状態をReducerへ保存する。再表示後に `requestAnimationFrame` で復元する |
| メモリ管理             | 非アクティブタブでは検索Range、Highlight Registry、Mermaid SVG、DOMイベントを破棄する。Markdown文字列と論理状態だけを保持する。必要になっても無制限キャッシュにはせず、実測後に上限付きLRUを検討する |
| 監視の集約             | 各ウィンドウが `sync_watch_targets(windowLabel, targets)` を呼び、Rust側の `WindowWatchRegistry` がウィンドウ別集合を保持する。実際のwatch/unwatchは全ウィンドウ和集合との差分だけ行う。ウィンドウ終了時は `remove_window_watch_targets(windowLabel)` を必ず呼ぶ |
| 同一ファイルの複数タブ | タブIDはパスではなく採番（`tab-1`, `tab-2`…）とし、同一パスの複数タブを許可する（要求4.1）                                                                                                                                               |
| ツールチップ           | `<div title={fullPath}>`。OSネイティブのツールチップで十分（要求4.2）                                                                                                                                                                    |
| 右クリックメニュー     | `ContextMenu.tsx` を新規作成。ファイル名コピー／フルパスコピー（`navigator.clipboard`）／閉じる／他を閉じる／右側を閉じる／別ウィンドウ／VSCode／メモ帳（要求4.3）                                                                       |
| 並び替え               | HTML5 Drag and Drop API（`draggable` + `dragover` で挿入位置算出）。外部へのドロップは扱わない（QA#5）                                                                                                                                   |
| 閉じたタブ復元         | `useClosedTabs.ts` にリングバッファ（上限50件、`{ path, scrollTop, foldState, search }`）。`Ctrl+Shift+T` でpopして復元（要求4.4）。復元開始後にタブが再度閉じられた場合、古い読込結果は `loadGeneration` で破棄する |
| 既存機能との衝突       | `Ctrl+W` はタブを閉じる。**最後の1タブを閉じた場合はウィンドウごと閉じる**（Chrome準拠）。クロップ編集中の `Esc` とタブ操作の競合は §2-9 のキーイベント優先順で整理                                                                      |

### 2-5. 見出し折りたたみ（req 8）— 本バージョンの技術的な山場

| 項目             | 内容                                                                                                                                                                                                                                                                                                       |
| :--------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 実装箇所         | 新規 `src/lib/rehypeFoldSections.ts`（rehypeプラグイン）, `src/hooks/useFold.ts`                                                                                                                                                                                                                           |
| 方式             | react-markdown が渡す **hast は見出しと本文がフラットに並んだ木**なので、そのままでは「見出し配下」を掴めない。rehypeプラグインで木を走査し、`h1`〜`h6` を起点に `<section data-fold-id data-level>` へ**ネストし直す**。閉じ位置は「次に現れる同階層以上の見出しの直前」で、要求8.2の定義と完全に一致する |
| 折りたたみ描画   | 折りたたみは `section[data-collapsed="true"] > :not(:first-child) { display: none }` のCSSだけで済む。**DOMを外さない**ので、折りたたみ範囲内も検索対象に残り（要求9.3）、スクロール位置の計算も壊れない                                                                                                   |
| トグルUI         | 見出しの `::before` ではなく実要素のボタン（`▼`/`▶`）を見出し左に配置。見出しテキストのクリックでもトグルする                                                                                                                                                                                              |
| fold-id          | `<レベル>:<見出しテキストの正規化>:<同名内の出現index>` で生成。ファイル内容が変わっても見出しテキストと階層で照合できるため、要求8.5「可能な範囲で復元」を満たす                                                                                                                                          |
| 全体開閉         | `Alt+Ctrl+T`。「1つでも展開されていれば全折りたたみ、全部折りたたみ済みなら全展開」（要求8.3）                                                                                                                                                                                                             |

### 2-9. ショートカットとキーイベントの優先順（req 18）

現状 [useMarkdownFile.ts:73](../../../src/hooks/useMarkdownFile.ts) が `window` に直接F5リスナーを付けているが、
タブごとにフックが動くと多重登録になる。**`useShortcuts.ts` へ一元化**し、以下の優先順で処理する。

1. クロップ編集中: `Enter`（適用）／`Esc`（キャンセル）を最優先で消費する
2. Mermaid拡大表示中: `Esc` で閉じる
3. 検索バー表示中: `Enter`／`Shift+Enter`（前後移動）／`Esc`（閉じる）
4. グローバル: `Ctrl+W` / `Ctrl+Shift+T` / `Ctrl+Tab` / `Ctrl+Shift+Tab` / `Ctrl+F` / `F5` / `Alt+Ctrl+T` / `Ctrl±0` / `F11`

`Ctrl+Tab` は WebView 既定のフォーカス移動を奪うため `preventDefault` が必須。

### 2-14. 非同期処理の共通ルール

- ファイル読込、シンタックスハイライト、Mermaid描画はタブ・ブロックごとの世代番号を持つ
- 新しい処理開始時に世代を増やし、完了時に世代不一致なら結果を捨てる
- ReactコンポーネントのcleanupでAbortController、Observer、Highlight、イベント購読を解除する
- Rustイベントには正規化済みパスを含め、フロント側では現在存在するタブだけへ配布する
- エラーはタブ状態へ保存し、非アクティブタブのエラーで現在タブの表示を置き換えない
