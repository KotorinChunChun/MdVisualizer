# MarkdownViewer v0.0.7 リリース自動化skill要求

作成日: 2026-08-10

## 目的

- MSIX、App Installer、配布サイト、FTP公開、HTTPS検証の反復作業を再利用可能にする。
- MarkdownViewerだけでなく、将来追加するWindowsアプリにも適用できる汎用skillとする。
- プロジェクト固有値はリポジトリ内の設定へ置き、skillへ固定値や秘密情報を埋め込まない。

## 最重要の安全要件

- リリース、テスト、release build、MSIX／App Installer生成、サイト配置、FTP公開は時間または外部変更を伴う。
- ユーザーがその操作を明示的に望んでいる場合だけ開始する。
- 「検討」「説明」「確認」「レビュー」「計画」では、読み取り専用のPlan以外を実行しない。
- オーケストレーターの既定モードはPlanとし、Build／Stage／Fullは明示的な確認switchがなければ開始前に失敗させる。
- FTP公開にはリリース確認とは別の公開確認switchを必須とする。
- Verifyは公開物の読み取り検証だけを行い、ビルド、配置、アップロード、インストールを開始しない。
- skillの検証ではPlanと拒否動作だけを使用し、MSIX生成、FTP公開、アプリインストールを行わない。

## 設定

- Package Identity、Publisher、architecture、証明書Friendly Name、website project、配布先、チャネルURLをJSON設定へ集約する。
- stableとbetaは同じIdentity／署名証明書を使い、別のApp Installer URIと配布ディレクトリを使う。
- バージョンと成果物名はTauri設定とMSIX manifestから取得し、スクリプトへ固定しない。
- FTP認証値は既存Webプロジェクトの`.env`から既存アップロードスクリプトが取得する。skillと設定へ保存しない。

## skill

- 個人skill名は `publish-msix-release` とする。
- `$CODEX_HOME/skills`配下へ公式`init_skill.py`で作成する。
- trigger descriptionにMSIX release、App Installer生成、stable／beta公開、配布検証を含める。
- skill本文は意図判定、安全なモード選択、検証、記録の順序に集中し、詳細な配布契約はreferenceへ分離する。
- `agents/openai.yaml`を作成し、`quick_validate.py`で検証する。

## 完了条件

- Planがファイル変更、ビルド、アップロードをせず設定と予定操作を表示する。
- Build／Stage／Fullが確認switchなしで、外部コマンド開始前に拒否される。
- Publish／Fullが公開確認switchなしで、FTP接続前に拒否される。
- stable／beta設定と任意の数値バージョンから成果物パス／URLを導出できる。
- 既存のv0.0.7-beta成果物を読み取りVerifyできる。
- skillの構造検証と非破壊forward testが成功する。
