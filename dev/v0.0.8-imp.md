# v0.0.8 実装計画・報告

## 要求

- `spmd:` 独自プロトコルからSharePointドキュメントライブラリ上のMarkdown文書を開く。
- URI形式は `spmd://{tenant}.sharepoint.com/{server-relative-path}` とする。
- 例: `spmd://excelchunchun.sharepoint.com/sites/msteams_fcce9d/Shared%20Documents/md/README.md`

## 実装方針

- URIは未信頼入力としてRust側で解析し、SharePointホスト、文書パス、拡張子、エンコードを検証する。
- Windows/TauriのDeep Linkと既存single-instance起動経路を統合し、初回起動・追加起動・別ウィンドウを同じ文書識別子で扱う。
- Microsoft Entra IDのデスクトップ公開クライアントとしてデバイスコード認証を行う。クライアントシークレットは使用しない。
- Microsoft Graphでサイト、ドキュメントライブラリ、driveItemを解決してMarkdown本文を取得する。
- SharePoint文書はローカルファイル監視・編集・外部エディター操作から分離し、再読み込みはGraphから再取得する。

## 実装報告

- Tauri Deep Linkへ`spmd`を登録し、初回起動、single-instanceの追加起動、別ウィンドウ起動を同じ文書識別子で扱うようにした。
- `spmd://{tenant}.sharepoint.com/{server-relative-path}`をRust側で解析し、SharePoint Onlineホスト、`/sites/`・`/teams/`、Markdown拡張子を許可した。ユーザー情報、ポート、クエリ、フラグメント、危険なエンコードは拒否する。
- 設定画面へMicrosoft EntraのクライアントIDとテナントを追加した。デバイスコード認証では既定ブラウザーとコード案内を表示し、アクセストークン・更新トークンはプロセス内だけで保持する。
- Microsoft Graphの委任された`Sites.Read.All`を使用し、site、document library、driveItemを順に解決して最大10 MBのMarkdown本文を取得する。
- SharePoint文書はタブ、再読み込み、印刷、別窓、同じSharePoint内の相対Markdownリンクに対応する。右クリックから元のSharePointページも開ける。
- ローカル専用のファイル監視、診断、外部エディター、画像編集をSharePoint文書では実行しない。相対画像の認証取得は今回の対象外とした。
- TauriのMSI／NSISとカスタムMSIXへ`spmd`関連付けを登録した。生成済みWiX、NSIS、AppxManifestで登録内容を確認した。
- フロントエンド59ファイル・289テスト、Rust 76テスト、TypeScript検査、Vite本番ビルド、Tauri releaseビルドが成功した。
- `MarkdownViewer_0.0.8_x64_en-US.msi`、`MarkdownViewer_0.0.8_x64-setup.exe`、自己署名の`MarkdownViewer_0.0.8.0_x64.msix`を生成した。
- 実テナントへのサインインと文書取得は、EntraクライアントIDおよび組織の同意が未提供のため未実施。設定・URI・Graphパス解決は単体テストで確認した。
