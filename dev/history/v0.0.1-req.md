# 爆速 Markdown Viewer 要求定義書

## 1. 概要

### 1.1 目的

本アプリケーションは、Markdownファイルを高速に表示し、元ファイルの変更をリアルタイムに反映することに特化した軽量ビューアーである。

機能は大幅に絞り、以下の2点を中核機能とする。

- Markdownファイルのリアルタイム更新表示
- Markdown内画像のクロップ編集

Markdownの編集機能、タブ機能、テーマ切り替え、Mermaid対応、ページ内検索、見出し折りたたみ等は本要求から除外する。

### 1.2 コンセプト

> Markdownを開いたまま、編集は外部エディタで行い、ビューアー側は即座に最新状態を表示する。

本アプリは、Markdownエディタではなく、外部エディタと併用するための自動更新ビューアーとして設計する。

### 1.3 想定利用シーン

- VSCode、メモ帳、その他エディタでMarkdownを編集しながら、別ウィンドウでプレビューする
- Markdownに埋め込まれた画像を確認し、その場で不要部分をクロップする
- 仕様書、README、メモ、手順書を軽量に確認する

## 2. スコープ

### 2.1 対象機能

本要求で対象とする機能は以下のみとする。

1. Markdown表示
2. Markdownファイルのリアルタイム更新
3. F5による手動リロード
4. Markdown内画像の表示
5. 画像クリックによるクロップ編集
6. クロップ後の画像ファイル更新
7. クロップ前画像の一時バックアップと復元
8. `.md` ファイル関連付け起動
9. 外部エディタで開く導線

### 2.2 対象外機能

以下は実装しない。

- Markdown本文の編集
- タブ機能
- タブ分離
- 複数プロセス管理
- Mermaid対応
- ページ内検索
- H1～H6見出し折りたたみ
- テーマ切り替え
- ズーム機能
- 表示モード切り替え
- フォルダを開くボタン
- ファイルを開くメニュー
- コードブロックのコピーボタン
- シンタックスハイライト
- ステータスバー
- 設定画面
- 目次表示
- PDF出力
- Git連携
- AI連携

## 3. 基本仕様

### 3.1 アプリ種別

デスクトップアプリケーションとする。

### 3.2 対応ファイル

最低限、以下の拡張子に対応する。

- `.md`
- `.markdown`

### 3.3 起動方法

以下の方法でMarkdownファイルを開けること。

- `.md` ファイルの関連付けから起動
- コマンドライン引数でMarkdownファイルパスを指定して起動
- OSの「プログラムから開く」で起動

例:

```text
MarkdownViewer.exe C:\Project\README.md
```

### 3.4 ファイルを開くメニュー

アプリ内に任意ファイルを開くためのメニューは持たない。

本アプリは「指定されたMarkdownファイルを表示する」ことに専念する。

## 4. 画面構成

### 4.1 基本画面

画面はできるだけシンプルにする。

```text
+------------------------------------------------------------+
| README.md                                      [VSCode]    |
+------------------------------------------------------------+
|                                                            |
|  Markdown プレビュー本文                                   |
|                                                            |
|  # 見出し                                                  |
|  本文...                                                   |
|                                                            |
|  ![画像](image.png)                                        |
|                                                            |
+------------------------------------------------------------+
```

### 4.2 UI要素

最低限のUI要素のみを表示する。

- 現在表示中のファイル名
- Markdown本文ビュー
- 外部エディタで開くボタン
- 画像編集時のクロップUI
- 必要時のトースト通知

### 4.3 UI方針

- 起動速度と表示速度を優先する
- 常時表示するボタンやメニューは最小限にする
- 設定画面は作らない
- ユーザーが普段触る機能は「外部エディタで開く」と「画像クロップ」のみに絞る

---

## 5. Markdown表示

### 5.1 基本表示

MarkdownファイルをHTML相当のプレビューとして表示する。

対応要素は最低限以下とする。

- 見出し
- 段落
- 箇条書き
- 番号付きリスト
- 引用
- コードブロック
- インラインコード
- リンク
- 画像
- 表
- 水平線

### 5.2 表示優先度

高度な装飾よりも、以下を優先する。

1. 起動速度
2. リロード速度
3. スクロールの軽さ
4. 表示崩れの少なさ
5. 画像表示の安定性

### 5.3 Markdown内HTML

Markdown内HTMLは安全性を考慮して制限する。

最低限、以下は実行または表示しない。

```html
<script></script>
<iframe></iframe>
<object></object>
<embed></embed>
```

## 6. リアルタイム更新

### 6.1 概要

表示中のMarkdownファイルが外部エディタ等で変更された場合、アプリは自動的に変更を検知して表示内容を更新する。

本機能を本アプリの最重要機能とする。

### 6.2 監視対象

監視対象は以下とする。

- 現在表示中のMarkdownファイル
- Markdownから参照されているローカル画像ファイル

### 6.3 Markdownファイル変更時の動作

Markdownファイルの変更を検知した場合、アプリは自動的にファイルを再読み込みし、表示を更新する。

要件:

- 外部エディタで保存された変更を自動反映する
- 更新時にアプリが点滅したり、過度にちらついたりしない
- 可能な限り現在のスクロール位置を維持する
- ファイル読み込み中に一時的に空白画面を表示しない
- 更新に失敗した場合は、直前の表示を維持する

### 6.4 画像ファイル変更時の動作

Markdown内で参照されている画像ファイルが更新された場合、該当画像の表示を更新する。

要件:

- 画像ファイルの更新を検知する
- ブラウザキャッシュ等により古い画像が表示され続けないようにする
- 画像更新時もMarkdown全体の再描画は必要最小限にする

### 6.5 手動リロード

ショートカット:

```text
F5
```

F5キーにより、現在表示中のMarkdownファイルを手動で再読み込みできる。

### 6.6 更新タイミング

リアルタイム更新は、保存途中の不完全なファイルを読み込まないようにする。

要件:

- ファイル変更イベントを検知しても即時読み込みせず、短い待機時間を設ける
- 短時間に複数の変更イベントが発生した場合はまとめて1回だけ更新する
- 目安として100msから500ms程度のデバウンスを行う

### 6.7 エラー時の扱い

ファイル更新時に読み込みエラーが発生した場合、以下のように扱う。

- 直前に正常表示できていた内容を維持する
- エラー内容を小さな通知で表示する
- 次回保存またはF5リロードで再読み込みを試行する

---

## 7. 画像表示

### 7.1 対応画像

Markdown内で参照されるローカル画像を表示する。

対応形式は最低限以下とする。

- PNG
- JPEG
- GIF
- WebP
- BMP

### 7.2 パス解決

画像パスは、Markdownファイルの存在するフォルダを基準に解決する。

対応するパス:

- 相対パス
- 絶対パス
- サブフォルダ内の画像

例:

```markdown
![sample](images/sample.png)
```

### 7.3 画像読み込み失敗時

画像が存在しない、破損している、読み込めない場合は、アプリがクラッシュせず、代替表示を行う。

表示例:

```text
画像を読み込めません: images/sample.png
```

---

## 8. 画像クロップ編集

### 8.1 概要

Markdown本文内の画像をクリックすると、画像クロップ編集モードに入る。

本機能は、Markdown文書に貼り付けたスクリーンショット等の不要部分を、ビューアー上で素早く切り取るために提供する。

### 8.2 編集開始

ユーザーがMarkdown本文内の画像をクリックした場合、対象画像を画像編集モードで表示する。

要件:

- クリックした画像のみを編集対象にする
- 編集対象画像のファイルパスを内部的に保持する
- 同じ画像が複数箇所に表示されている場合でも、元画像ファイルは同一として扱う

### 8.3 クロップUI

画像編集モードでは、画像上にクロップ範囲を示す矩形を表示する。

矩形には以下のドラッグハンドルを配置する。

- 左上
- 上
- 右上
- 右
- 右下
- 下
- 左下
- 左

### 8.4 クロップ操作

ユーザーはハンドルをドラッグしてクロップ範囲を変更できる。

要件:

- 四隅のドラッグで縦横同時に範囲変更できる
- 辺のドラッグで一方向に範囲変更できる
- ドラッグ中はクロップ後の範囲が分かるように表示する
- クロップ範囲が画像外に出ないよう制限する
- 最小クロップサイズを設け、0pxや極端に小さい範囲にならないようにする

### 8.5 確定操作

クロップを確定すると、対象画像ファイルを更新する。

確定方法:

- Enterキー
- 画面上の「適用」ボタン

要件:

- クロップ確定時に元画像ファイルを上書き保存する
- 保存後、Markdownビューに戻る
- 保存後、Markdown本文内の該当画像表示を即座に更新する
- 保存成功時はトースト通知を表示する

表示例:

```text
image.png を更新しました
```

### 8.6 キャンセル操作

クロップをキャンセルした場合、画像ファイルは更新しない。

キャンセル方法:

- Escキー
- 画面上の「キャンセル」ボタン

### 8.7 元に戻す

画像クロップは元ファイルを更新するため、アプリ起動中は元に戻す操作を提供する。

要件:

- 画像編集前に元画像を一時フォルダへバックアップする
- アプリ起動中はバックアップから復元できる
- 画像単位で復元できる
- 復元後、Markdownビューの画像表示を更新する

表示例:

```text
image.png を更新しました  [元に戻す]
```

### 8.8 一時バックアップ

画像編集前のバックアップは、OSの一時フォルダに保存する。

要件:

- バックアップはアプリ起動中のみ保持する
- アプリ終了時に一時バックアップを削除する
- 同一画像を複数回クロップした場合でも、最初の編集前画像に戻せることを基本とする
- バックアップ作成に失敗した場合は、クロップ確定前に警告する

### 8.9 対応外ケース

以下の場合、画像クロップ編集は実行しない。

- 画像がリモートURLである
- 画像ファイルが読み取り専用である
- 画像ファイルに書き込み権限がない
- 画像形式が保存に対応していない
- 画像ファイルが破損している

この場合は、ユーザーに理由を通知する。

---

## 9. 外部エディタ連携

### 9.1 基本方針

Markdown本文の編集はアプリ内では行わない。

編集が必要な場合は、外部エディタで開く。

### 9.2 外部エディタで開く

最低限、現在表示中のMarkdownファイルをOS既定のエディタ、またはVSCodeで開く導線を用意する。

UI例:

```text
[VSCodeで開く]
```

### 9.3 編集後の反映

外部エディタでMarkdownを編集して保存すると、リアルタイム更新機能によりビューアー側の表示が自動更新される。

---

## 10. 非機能要件

### 10.1 起動性能

本アプリは軽量起動を重視する。

目標:

- 通常起動: 300ms以下
- 理想値: 100ms以下
- `.md` 関連付け起動時も体感的に即時表示されること

### 10.2 更新性能

Markdown保存後、可能な限り短時間でビューに反映する。

目標:

- 通常のMarkdown更新: 500ms以内に反映
- 小規模Markdown: 200ms以内に反映
- 画像更新: 500ms以内に反映

### 10.3 安定性

以下の状況でクラッシュしないこと。

- Markdownファイルが削除された
- Markdownファイルが保存途中で一時的に空になった
- ファイルアクセス権限がない
- 画像ファイルが削除された
- 画像ファイルが破損している
- 画像クロップ保存に失敗した

### 10.4 データ保護

画像クロップは元ファイルを更新するため、データ保護を重視する。

要件:

- クロップ前にバックアップを作成する
- バックアップ作成失敗時は原則として上書き保存しない
- 保存失敗時に元ファイルを破損させない
- 保存処理は可能であれば一時ファイルに書き出してから置換する

## 12. MVP範囲

初回リリースでは、以下を実装対象とする。

- `.md` ファイルの関連付け起動
- Markdown表示
- Markdownファイル変更のリアルタイム更新
- 参照画像ファイル変更のリアルタイム更新
- F5手動リロード
- Markdown内画像の表示
- 画像クリックによるクロップ編集モード
- 四隅と四辺のドラッグによるクロップ範囲指定
- クロップ確定による画像ファイル上書き保存
- クロップ前画像の一時バックアップ
- アプリ起動中の元に戻す
- 外部エディタで開くボタン

---

## 13. まとめ

本アプリは、機能を大幅に削り、以下の2つに集中する。

1. Markdownを外部編集に追従してリアルタイム更新する
2. Markdown内画像をクリックして、その場でクロップ編集する

余計な機能を持たせないことで、起動速度、更新速度、操作の単純さを優先する。

本アプリの価値は、Markdown編集環境の補助ビューアーとして、軽く、速く、画像整理にも強いことにある。
