## 1. 目的と確定した要求

### CLI先行実装への変更（2026-09-13）

ユーザー指示「まずは出力機能だけを単独で開発」「CLIで動作できるような独立機能」を本書のアプリ統合手順より優先する。

- 入力はローカルMarkdownファイル、または標準入力のMarkdown本文。標準入力には相対参照の基準ディレクトリーを指定できる。
- `node scripts/export-html.mjs 入力.md --output 出力.html`を入口とする。Node.jsと既存のChromium系ブラウザーで生成し、生成HTMLの閲覧にはこれらの生成環境を不要とする。
- 配色は`--theme`、本文カスタムCSSは`--css`で受け取る。既定はアプリのdarkテーマ。起動中アプリや利用者の保存済み設定を直接読まない。
- 全文・全行・全列・図表示を固定し、アプリの編集・保存・印刷・ボタンを変更しない。
- HTTP(S)資産は`--allow-remote`の明示時だけ取得する。draw.ioは描画時に既存ビューアーが必要で、ネット取得を許可するか`--drawio-viewer`で手元のviewer-static.min.jsを指定する。
- SharePoint認証・起動中タブ・一時アセットの取得はホスト統合時のadapterとして残す。CLIはローカル保存済み文書・資産と標準入力を対象とし、アプリの認証へ結合しない。
- HTMLラベルを含む図は、生成用ブラウザーでその図要素だけをPNGとして取得し、文字を近似変換せず埋め込む。文章全体は画像化しない。
- 保存先が既存なら`--force`を要求し、失敗時に既存ファイルを変更しない。

以下のアプリ操作・未保存タブ取得・SPFxの記述は後続統合用の設計として保持する。

現在開いているMarkdownのプレビュー内容を、一つの`.html`ファイルとして持ち出せるようにする。受け取った人はMdVisualizer、Markdown原本、画像フォルダー、描画エンジン、ネット接続を用意せず、ブラウザーで内容を閲覧できる。

- アプリの「印刷/PDF」ボタンのすぐ右に「HTML出力」ボタンを置く。
- 出力内容は閲覧用の本文、見出し、表、コード、画像、図とする。
- 編集、コピー、プレビュー切替、右クリックメニュー、目次パネル、検索欄、AI、Markdown連携、Mermaid連携などのアプリ機能を出力しない。
- 出力HTMLにはReact、Markdownパーサー、Mermaid、draw.ioビューアーなどの実行用JavaScriptを含めない。
- SVG・PNG等への変換方式と埋め込み方法は設計側で選定する。
- 実装対象はWindowsデスクトップ版のみとする。デスクトップ版で開いたSharePoint文書も出力対象に含める。
- 折りたたみ・表の絞り込みを解除し、文書全文・全行・全列を出力する。図は図表示とする。
- 出力の配色は現在のプレビューに合わせる。
- 今回は設計書を作成し、不明点をまとめて質問する。回答だけで実装開始とは扱わず、次の実装指示を受けて着手する。

## 2. 採用する方式

**本文はHTML、図はSVGまたはPNG、画像はData URL、スタイルはHTML内のCSSとして保存する。**

Base64は画像形式ではなく、画像のバイト列をHTMLへ格納する符号化方式である。したがって「SVGかBase64か」の二択ではなく、SVGもPNGも必要に応じてBase64で埋め込む。Data URLはMIME型とデータを一つのURLに格納する形式である。[MDN: Data URL](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Schemes/data)

| 内容 | 保存形式 | 選定理由 |
|---|---|---|
| 本文・見出し・箇条書き・引用 | 意味を保ったHTML | 画面幅に応じて折り返せ、本文の選択やブラウザー標準検索も使える |
| 通常コード | `pre` / `code`とハイライト済みの要素・CSS | 閲覧時のハイライトエンジンを不要にする |
| Markdown表・CSV/TSV表 | 静的な`table` | ボタン、ページ送り、検索処理を持ち出さずに読める |
| 自己完結できるSVG図 | `img`のSVG Data URL | 拡大時の鮮明さを保ち、文書本体とSVGのID・CSSを分離する |
| SVGのままでは表示互換性を保ちにくい図 | PNGのData URL | HTMLラベルやフォント依存の強い図を、出力時の見た目で固定する |
| PNG/JPEG/GIF/WebP等 | 元形式のData URLを基本とする | 不要な再圧縮を避ける。未対応形式の変換はアプリで復号できる場合に限る |

文書全体の画像化は採用しない。長文で大きな画像が必要になり、小さい画面での折り返しや本文の選択ができなくなるためである。SVG画像として使用する場合にも、内部の外部画像・外部CSSなどは埋め込みが必要となる。[MDN: SVGを画像として使用する場合の制約](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_as_an_image)

## 3. 動作環境と保証の範囲

- 検証対象は、現在利用されているEdge、Chrome、Firefox、Safari系の通常ブラウザーとする。PCに加え、Android・iPhone/iPadでの閲覧を想定する。
- `.html`をローカルファイルとして開く場合と、通常のWebサーバーから配信する場合を扱う。閲覧時のサーバー処理は不要。
- JavaScriptを無効化し、ネットワークを遮断した状態でも本文・表・図・画像が表示されることを受入条件とする。
- OSごとの標準フォントの違いによる字形・改行位置の完全一致までは保証しない。本文には代替フォントを指定する。図でフォント差による欠けが生じる場合はPNG化する。
- HTMLの実行やData URLを禁止・改変するメール本文、サービス内の簡易プレビュー、管理者制限、古い独自ブラウザーは別扱いとする。iOS等のファイルアプリ内プレビューと通常ブラウザーも区別して結果を記録する。
- 「どのような環境でも」は、無制限の互換保証ではなく、外部依存のない標準HTMLを対応ブラウザーで閲覧できることとして具体化する。

## 4. 出力内容の基準

### 4.1 対象文書と未保存内容

- ボタンを押した時点のアクティブなMarkdownタブの最新の下書きを対象にする。ディスク上の古い本文を再読込して出力しない。
- 未保存の新規Markdownも対象とし、元Markdownを先に保存させない。
- 未保存画像・未保存外部図等は、現在のタブが持つ一時アセットを参照する。出力のためにMarkdownへ保存・確定しない。
- 文書ID、世代、本文、参照元ディレクトリー、参照画像の版、一時アセット、表示設定を出力セッションのスナップショットとして固定する。
- 通常画面のプレビューは`useDeferredValue`で遅延するため、表示中DOMだけを即コピーする実装にしない。出力は取得した最新本文から準備する。
- 出力中の編集・タブ切替があっても別文書や異なる世代を混在させない。一時アセットを処理終了まで保持し、保持できない変更が起きた場合は中止する。

### 4.2 本文の範囲（Q2回答で確定）

**文書全体を展開した連続したページ**とする。

- 折りたたまれている見出し・コードも全文を含める。
- CSV/TSV表は全行・全列を原本順で含め、画面のページ送り・一時検索・絞り込み・非表示列の影響を受けない。集計済みの値は静的なセル値にする。
- 図は通常の図表示にする。図をコード表示に切り替えていた場合でも、図のソースを閲覧機能と一緒に持ち出さない。
- プレゼン表示等からも同じMarkdown本文全体を出力する。現在のスライドだけには限定しない。
- 本文に書かれた目次風のリストは本文として残す。アプリが生成する目次パネルは含めない。

2026-09-13の回答により、現在の折りたたみ・表の絞り込み結果を固定する案は採用せず、全文・全行・全列の出力で確定した。

### 4.3 見た目（Q3回答で確定）

現在のプレビューの色、文字サイズ、行間、画像表示サイズ、コード配色を基準にする。ダークテーマを含め、出力先OSのテーマで自動変化させない。2026-09-13の回答により、白背景・黒文字への統一ではなく、現在の配色の保持で確定した。

- アプリのサイドバー幅やスクロール領域は含めず、読みやすい最大本文幅と左右余白を設ける。
- 本文と画像は画面幅に追従させる。幅広の表・コードは内容を切らず、必要な場合だけ横スクロールできるようにする。
- 印刷専用の色、ページ分割、印刷日時、元ファイルのパスは自動付加しない。
- 任意カスタムCSSは内容に適用するが、アプリ操作用の規則や外部参照をそのまま持ち出さない。選択した表示を静的に再現できない規則は黙って捨てず、該当内容を通知する。

### 4.4 操作とリンク

- ツールバー、編集ダイアログ、リサイズハンドル、表のソートボタン、ページ送り、図の表示切替、AIの操作、独自右クリックメニューをDOMから除外する。CSSで隠すだけにはしない。
- 表の見出しなど、ボタン内に本文が含まれる場合は本文を通常のテキスト要素へ移して保持する。
- チェックリストはチェック済み・未チェックの状態を静的な記号と読み上げ用の説明で表示する。変更用入力欄は含めない。
- 本文の文字選択、ブラウザー標準のコピー・検索・印刷・右クリックは妨げない。「コピー機能ボタン不要」はコピー禁止とは解釈しない。
- 同じ文書内のアンカーと通常のHTTP(S)リンクは保持する。リンク先文書の自動取得は行わない。外部ページの閲覧には別途ネット接続が必要。
- ローカルパス、相対Markdownリンク、`spmd:`などアプリ専用リンクは表示文字列を保持して非リンク化する。本文に明示されたパス文字列まで削除するものではない。
- 図の内部リンクやイベントは除去し、図を静的な画像として表示する。

## 5. アプリ内の操作

配置:

```text
[新規MD] [印刷/PDF] [HTML出力] [診断…] [再読込] [保存]
```

1. Markdownタブで「HTML出力」を押す。
2. アクティブ文書のスナップショットを取得し、保存先ダイアログを表示する。
3. 既定名を元ファイルの拡張子を除いた`文書名.html`とする。新規文書は`無題.html`とする。
4. 保存先が決まったら「HTML出力中…」を表示し、本文・図・画像を準備する。長時間処理にはアプリ内に進捗と中止操作を用意する。
5. 完全性を検査したHTMLを保存し、完了を通知する。出力ファイルやブラウザーを自動起動しない。

- Markdown未選択・設定画面・Markdown以外の単独SVG等では無効とする。対象形式の追加は別要求とする。
- 編集のみ表示でも下書きから生成可能とする。印刷中・HTML出力中は二重実行させない。
- 保存ダイアログのキャンセルは正常な中止。失敗時は保存成功を通知しない。
- 出力によって元Markdownのdirty状態、保存場所、折りたたみ、選択位置、スクロール、画像設定、クリップボードを変更しない。
- 同名HTMLの上書きは保存ダイアログで確認する。Markdownや元画像への上書きを許可しない。

## 7. 処理構成

```text
HTML出力ボタン
  → 最新本文・一時アセット・表示設定を固定
  → 保存先選択
  → 出力用プレビューの準備と全コンテンツの描画
  → 図のSVG/PNG化・画像のData URL化
  → 本文DOM・CSSの整形と不要要素の除去
  → 外部依存・欠落・禁止要素の検査
  → 単一HTMLの原子的保存
  → 出力用ホストと一時参照を解放
```

### 7.1 出力用の描画

- 既存Markdownの構文処理を共有し、文書解釈を別実装に複製しない。
- `staticMode`を変更して差分等の既存機能を壊さず、明示的な出力コンテキストを追加する。
- 出力専用ホストは実寸でレイアウトできる状態に置き、画面操作やフォーカスの対象にしない。`display:none`には依存しない。
- 見出し・表・通常コード・図・画像ごとに出力向けの表示を組み立てる。図・表を描画しつつ操作UIだけを作らない。
- Markdown内の図や外部ファイル参照、一時アセット、コード色付け、画像decode、フォント準備の完了を出力セッション内で追跡する。
- Mermaidの画面内判定を出力時だけ省略する。一般の印刷用・アプリ全体の描画ステータスから完了を推測しない。
- 状態を`pending / ready / error`で管理し、本文中の期待ブロックと結果を照合する。図が0件なのか、未描画なのかを区別する。

### 7.2 SVGとPNG

- 同一ソース・同一テーマ・同一版の完成済み図を再利用し、不足する図だけ描画する。キャッシュ不一致の図は再利用しない。
- SVGを独立した画像として表示できるように、寸法・viewBox・必要なスタイル・背景・色・内部参照を確定する。
- `foreignObject`によるHTMLラベル、外部フォント、SVG内画像等を調べる。自己完結した安全なSVGとして品質を確保できるものはSVGにし、それ以外はPNG化する。
- HTMLラベルを単に削除したり、近似的なテキスト置換で正常扱いにしたりしない。PNG化でも、変換前にラベルを失う既存のクリップボード経路をそのまま使わない。
- draw.ioでは正規化前の完成SVGを出力経路へ渡せるようにする。メッセージ送信元のiframeとセッションを検証し、他のiframeの結果を採用しない。
- PNG化は原寸と拡大表示を考慮した解像度で行い、最大辺・画素数・メモリ量を制限する。無制限な高解像度化や文書全体の巨大canvasは使わない。
- 日本語の長いラベル、複数行、HTML装飾、図内画像、ダーク背景の試作結果を実装初期の判定点とする。自己完結後のSVGを復号・ラスタライズできない場合は、欠けた画像で代替せずエラーにする。
- 元のMermaidソース、draw.io編集用XML、SVG内の編集メタデータ、イベント、外部リンクは出力画像へ残さない。図の説明・代替テキストはHTML側で保持する。

### 7.3 画像・外部参照

- 一時アセットを優先し、次に文書の参照元を基準として読み込む。保存先HTMLのディレクトリーを画像解決の基準にしない。
- ローカルの相対・絶対画像参照は、出力専用の読込経路で正規化・サイズ・形式を検査して読み込む。既存`readDocumentAsset`の許可範囲を無条件には広げない。
- SharePoint由来の画像は既存の認証経路で取得する。資格情報や認証付き取得URLはHTMLへ記録しない。
- HTTP(S)画像は実際の参照先に限って取得し、Data URL化する。表示済みでもバイト列を取得できるとは限らないため、CORSや認証の失敗を検出する。
- 必要なネイティブHTTP取得は、参照画像に限定したAPIとして設計する。任意ページの巡回や認証Cookieの無差別な転送をしない。リダイレクト後も形式・サイズ・取得範囲を検査する。
- SVG内の`image`、外部`use`、CSSの`url()`等も対象とする。HTML表面の`img.src`だけを検査して完了としない。
- Base64やData URLの入力はMIME型・実データ・SVG内部まで検証する。`blob:`、`asset:`、Tauri固有URL、`file:`、外部画像URLを出力資産として残さない。
- 図や画像の準備時はネット接続が必要な場合がある。特に未描画のdraw.ioは現行の外部ビューアーに依存する。**完成したHTMLの閲覧時はネット接続不要**という保証と区別する。

### 7.4 CSS・最終HTML

- 基本文書CSS、コード配色、本文設定、必要なカスタムスタイルを一つの`style`へまとめる。アプリ全体のCSSや外部CSSファイルをコピーしない。
- 通常のセレクターを基礎にして、色等のCSS変数を出力時に解決する。必要な`:scope`・テーマ依存・疑似要素の内容は出力ホストの計算結果または変換した規則から保持する。
- 外部フォントは必須にしない。本文は標準フォントの代替指定を使い、画像・図に必要な外部資産は埋め込むか静的変換する。
- `@import`、外部`url()`、外部スタイルシート、リソース先読み、`base`、refresh、フォーム、実行スクリプト、イベント属性、アプリ用`data-*`・編集属性を除く。
- SVG内を含めた許可要素・属性・URLの検査を行う。Data URLへの符号化はサニタイズの代わりにはしない。
- HTMLのタイトル・属性・本文は適切にエスケープし、CSSの`</style>`混入も防止する。
- UTF-8、`<!doctype html>`、`lang`、`meta charset`、`viewport`、`title`を付ける。タイトルはファイル名等の表示名とし、フルパスや生成日時を本文へ追加しない。
- CSPを補助として文書先頭へ設定する。案は`default-src 'none'; img-src data:; style-src 'unsafe-inline'; script-src 'none'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'`。生成物そのものの検査を必須とし、CSPだけに依存しない。HTMLのmetaからCSPを設定できる。[MDN: meta http-equiv](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/http-equiv)

### 7.5 保存・失敗・容量

- HTML専用の保存コマンドを追加し、絶対パス、`.html` / `.htm`、元文書・参照資産との別パス、上書き対象を確認する。
- 完成データを同じディレクトリーの一時ファイルに書き、書き込み完了後に置換する。キャンセル、ディスク不足、書込不可では既存HTMLを保護する。
- 図の描画失敗、画像取得失敗、外部依存の残存、容量制限超過では保存を中止し、文書中の該当位置・表示名・理由をアプリ内で示す。URLの認証情報・トークンは通知やログに含めない。
- 失敗した図のソースコードや「読み込み中」のプレースホルダーを、成功したプレビューとして保存しない。欠落を許して続行するモードは初期実装に設けない。
- 資産ごとの取得制限、総出力サイズ、図の描画タイムアウト、同時実行数を実装定数として一箇所で管理する。数値は既存の図の上限と代表文書での実測から決定し、実装報告に記録する。
- Base64は概ね元データの4/3の容量を使う。大きな画像はファイルサイズを支配するが、既定で勝手に縮小・劣化させない。
- 同じ資産の取得・変換は共有する。Data URLの複数箇所への格納による最終HTMLの重複は容量計算に含める。
