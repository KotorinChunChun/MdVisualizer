## 1. 実装原則

* 検索、診断、目次はMarkdownソース上の位置と表示DOM上のアンカーを分離し、行番号と本文ジャンプを安定させる。
* 検索結果および診断結果からの移動は、既存の折りたたみ展開処理とnavigation snapshotを共通利用する。
* 通常表示とプレゼン表示で検索モデルを共有し、表示先の決定だけを各レイアウトのadapterへ分ける。
* 印刷は画面状態を直接破壊せず、印刷セッションに一時状態を保持して`afterprint`で必ず復元する。
* 診断は表示を妨げない非ブロッキング機能とし、エラーがあっても印刷・外部アプリ連携を許可する。
* ドロワー／モーダルはフォーカストラップ、Escによる終了、起点へのフォーカス復帰を共通化する。
* GUI自動操作では、アプリ表示後5秒間の人間入力監視を行い、入力検知時は自動操作を開始せず明示的な再承認まで停止する。

## 3. 共通データモデル

### 3.1 ソース位置と表示アンカー

検索・診断で共通利用する`SourceLocation`を、行番号、列範囲、見出しID、折りたたみ親ID、
表示アンカーから構成する。Markdown解析時に見出し区間とブロックの対応表を生成し、通常表示ではDOMアンカー、
プレゼン表示では見出しIDからページIDへ解決する。ジャンプ前に現在状態を履歴へ記録し、親を展開してから移動・強調する。

### 3.2 パネル状態

検索結果と診断結果はタブごとに保持し、文書切替時の結果混入を防ぐ。選択行、開閉状態、検索条件、文脈行数を
タブ状態へ追加する。強調表示は一時的な表示状態とし、Markdown本文そのものは変更しない。

## 4. 要件別実装方針

### 4.1 検索結果パネル

既存の文字列、大小文字、正規表現オプションを純粋な検索条件モデルへ移す。Markdownソースを行単位で検索し、
一致行の前後0～5行、1-based行番号、所属する見出し階層、一致範囲を`SearchResult`として生成する。
同じ文脈範囲が重なる結果も一致単位で選択可能にし、描画時だけ安全にハイライトする。

入力は短いdebounce後に計算し、条件または文書が変わった場合は前回計算を無効化する。501件目を検出した時点で
走査を停止し、500件表示と打ち切りメッセージを返す。不正な正規表現は構文エラーを検索入力の近くへ関連付けて表示する。

結果パネルは矢印キーで選択、Enterで移動、Escで閉じる。移動処理は通常表示とプレゼン表示のadapterへ委譲する。
プレゼンでは該当見出しページを選び、ページ内の一致箇所を強調する。検索UIにフォーカスがある間、入力に使う左右キーを
PresentationViewのページ送りから除外する。

### 4.2 文書診断

MarkdownソースからローカルMarkdownリンク、同一／別文書の見出しアンカー、画像参照、見出しID、画像altを抽出する。
URLデコード後のパスを現在文書基準で正規化し、HTTP等の外部URLは存在検査の対象外とする。

同一文書内の見出しID衝突と空altはフロントエンドの純粋診断で警告にする。ファイル存在確認と参照先Markdownの
見出し一覧取得はTauri commandへ集約し、ブラウザー側から任意パスを直接扱わない。結果は重要度、種別、1-based行番号、
参照文字列、理由を持つ。ファイルごとの失敗は診断項目として返し、全診断を失敗させない。

現在文書と診断対象となったローカル参照先をwatch targetへ同期する。変更通知は短時間にまとめ、世代番号で古い結果を破棄して
再診断する。診断パネルは重要度をアイコンと文言でも示し、キーボード選択と履歴付き本文ジャンプを提供する。

### 4.3 印刷とPDF出力

`Ctrl+P`はブラウザー既定動作へ任せず、印刷設定の確定、準備、`window.print()`、復元からなる印刷セッションを開始する。
設定はレイアウト、折りたたみ、タイトル、元ファイル名、印刷日時、ページ番号の表示有無を持つ。

印刷開始時に表示モード、スクロール位置、折りたたみ状態、現在ページをsnapshotへ保存する。必要なら印刷専用DOMで
折りたたみを展開し、Mermaid statusが描画完了またはエラー確定になるまで待つ。無期限待機を避けるためタイムアウト時は
状態を説明して続行／中止を選べるようにする。`afterprint`、キャンセル、例外のすべてでsnapshotを復元する。

`@media print`ではタブ、ヘッダー、ステータスバー、サイドバー、目次、検索・診断パネル、操作ボタンを除外し、
テーマ非依存のライト配色と紙面用余白を適用する。通常表示は連続フロー、プレゼン表示は全スライドを印刷DOMへ並べて
各スライド末尾で改ページする。見出しと直後の本文、表、コード、画像には適切な`break-*`規則を指定する。
ページ番号等はブラウザー印刷機能の制約を明記し、対応可能な範囲を自動テストと実機PDFで確認する。

### 4.4 目次の現在位置表示

Markdown本文コンテナ上の`pointermove`をrequestAnimationFrame単位で間引く。ポインター座標にある要素から最寄りの
見出し区間を、事前生成した見出し境界または`data-*`属性で解決し、その見出しIDだけを目次のactive状態へ反映する。

スクロールリスナーからactive見出しを更新する既存経路は廃止する。`pointerleave`では最後のactive項目を維持する。
目次クリック直後は移動先IDを即時点灯し、次の本文内`pointermove`が発生するまでクリック由来状態を保持する。
タッチ／キーボード利用時も目次クリック・フォーカスによる点灯が失われない設計にする。

### 4.5 ウィンドウ位置・サイズと複数ウィンドウ

アプリ設定へ、次回の主ウィンドウに適用する位置と外枠サイズを保存する。終了時に最終的に閉じる
ウィンドウの実座標・サイズを保存し、起動時に復元する。保存済み座標が接続中のいずれの画面にも
表示されない場合は、主画面の作業領域内へ補正して表示する。

別窓作成コマンドは呼び出し元の`WebviewWindow`を受け取り、外枠位置・サイズ、現在のモニターを
取得する。新規ウィンドウは呼び出し元と同じサイズで、真右に収まる場合は真右、収まらない場合は
真左へ生成する。生成時点で作業領域を超える場合は、ウィンドウの可視領域を確保する位置へ補正する。

OSからMarkdownファイルを開いたときも既存プロセス内で同じ配置規則を使うため、Tauriの単一起動
プラグインを最初に初期化する。追加起動の引数からMarkdownファイルだけを正規化・重複除去し、
既存プロセスへ渡して新規ビューアウィンドウを生成する。初回起動時の引数処理とこの経路は共通化する。

### 4.6 VS Code連携と外部操作

VS Code起動前に`code --status`で全VS Codeウィンドウのワークスペース名を取得し、
`%APPDATA%\Code\User\workspaceStorage`の`workspace.json`からフォルダまたは`.code-workspace`へ解決する。
フォルダワークスペースは対象Markdownが配下にあるかを判定し、マルチルートワークスペースはJSONC形式の
`folders`を展開して各ルートとの包含関係を判定する。複数の起動中ワークスペースが対象を含む場合は、
対象ファイルに最も近いルートを持つワークスペースを選ぶ。パスは正規化し、Windowsでは大文字小文字を
区別しない。

同名の保存済みワークスペースが複数の異なるパスへ解決される場合や、状態取得・JSON解析に失敗した場合は
既存ワークスペースとみなさない。既存の包含関係を確認できた場合だけワークスペース＋ファイル引数で開く。
該当がない場合は対象ファイルの親から上位へ探索し、対象を含む`.code-workspace`、`.git`、`.vscode`、
主要プロジェクト定義、`.claude`／`AGENTS.md`の優先順で新規ワークスペースを推定する。ユーザーホームでは
探索を停止し、候補がなければ対象ファイルの親を使う。新規起動には必ず`--new-window`を付け、既存の別
ワークスペースを置き換えない。

`ExternalActions`には本アプリ内の「別窓で開く」を固定操作として追加する。外部アプリ設定と混同しない
よう、対象ファイルの有無と同じエラー通知経路を利用する。「その他」メニューはトリガーを基準とした
絶対配置の`role=menu`として表示し、ツールバーのレイアウトフローから除外する。

### 4.7 検索UIと表示倍率

検索開始ボタンと検索入力を同じ操作グループ内へ置き、開いたときだけ入力ボックスを検索ボタンの隣に
表示する。複数結果がある場合は`document-workspace`の左側に検索結果用サイドパネルを追加する。目次パネルと
同じ開閉・モバイルオーバーレイ・キーボード操作の規約を再利用し、1件以下では結果サイドパネルを表示しない。

表示倍率は50%から200%までの10%単位へ正規化する。`Ctrl`+ホイールはプレビューコンテナ上だけで捕捉し、
ブラウザー既定のズームを抑止して1ホイール操作につき10%変更する。プレゼン表示の固定倍率と、画像編集時の
座標計算を回帰テストする。

### 4.8 Obsidian画像埋め込みとキャプション配置

remarkプラグインでテキストノード内の`![[画像]]`／`[[画像]]`を画像ASTへ変換する。画像拡張子を持つ参照だけを
対象とし、コード、通常のノートリンク、既存Markdown画像は変更しない。`|代替テキスト`はaltへ変換し、数値の
サイズ指定はキャプションとして表示しない。画像一覧のソース位置モデルにも同じremark変換を適用する。

RustのMarkdown読込ではObsidian画像パスも抽出し、既存の画像ファイル監視へ渡す。画像レンダラーは画像本体と
リサイズオーバーレイを専用ステージへまとめ、キャプションをステージ外へ配置する。これにより表示サイズの高さを
画像本体だけに適用し、下側リサイズ枠とキャプションの重なりを防ぐ。

## 5. アクセシビリティと入力ルーティング

* 検索結果と診断一覧はlistbox相当の選択モデル、選択件数・エラーはlive regionで通知する。
* 現在選択、警告、エラーはアイコン、文言、`aria-*`を併用し、色だけに依存しない。
* 印刷設定、ドロワー、モーダルはフォーカストラップと起点復帰を検証する。
* Appのキー処理は、モーダル、検索入力、診断一覧、プレゼンの優先順位を明示し、処理済みイベントを再処理しない。
* `prefers-reduced-motion`時はジャンプ強調やパネル遷移の不要なアニメーションを無効化する。

## 7. 検証計画

### 7.1 自動テスト

* 検索: 0／500／501件、文脈0／2／5行、大小文字、正規表現、不正な正規表現、debounce世代破棄。
* ジャンプ: 折りたたみ親の展開、通常／プレゼンの表示先、履歴の戻る・進む、強調解除。
* 診断: 相対／絶対パス、URLエンコード、同一／別文書アンカー、欠落文書・画像、重複ID、空alt、部分失敗。
* 監視: 現在文書と参照先のtarget同期、変更イベント集約、古い診断結果の破棄。
* 印刷: UI除外、ライト配色、設定反映、通常連続フロー、スライド改ページ、状態復元、Mermaid成功・失敗・タイムアウト。
* 目次: 見出し区間の境界、pointermove間引き、pointerleave維持、スクロール非連動、クリック後の状態遷移。
* 入力: 検索・診断・印刷のキーボード完結、プレゼン左右キー競合、フォーカス復帰、reduced motion。
* ウィンドウ: 保存・復元、画面外補正、真右／真左配置、同一ファイルの独立別窓、起動中の追加ファイル引数。
* 外部連携: VS Codeへ渡すフォルダ・ファイル・新規ウィンドウ引数、別窓ボタン、ポップアップメニューの開閉とフォーカス。
* 検索UI／倍率: 検索ボタンと入力の隣接、複数結果だけの左パネル、10%段階、Ctrl+ホイール、保存値の移行。
* Obsidian画像: `![[...]]`／`[[...]]`、alias、非画像Wikiリンク、コード内記法、画像一覧、監視パス、キャプション構造。

### 7.2 GUI／実機テスト

通常表示とプレゼン表示の両方で、検索ジャンプ、診断ジャンプ、目次点灯を実WebViewで確認する。
ダークテーマからMicrosoft Print to PDFを実行し、ライト配色、通常の連続ページ、プレゼンの1スライド1ページ、
UIと目次の非出力、Mermaid・長い表・コード・画像の分割、印刷前後の状態復元を目視確認する。

GUI自動操作を開始する場合は、対象アプリ表示後5秒間、マウスとキーボードの人間入力を監視する。
入力を検知した回は追加操作を送らず中止し、ユーザーから明示的な再開承認を得る。

さらに、単一画面と複数画面、右端・左端に寄せた起点ウィンドウで別窓配置を確認する。起動済みの
MarkdownViewerへOSの関連付けから別Markdownを渡し、新規ウィンドウとして開くことを確認する。VS Codeは
対象フォルダを開いた既存ウィンドウがある場合とない場合の両方で、フォルダと対象ファイルが正しく開くことを
実機確認する。

| React MarkdownのDOMとソース行の対応ずれ | ソース位置モデルと安定した`data-*`アンカーをテストfixtureで固定する |
| 大規模文書での検索・診断負荷 | debounce、500件打ち切り、世代破棄、必要なら処理時間を計測する |
| OS／WebViewごとの印刷差 | CSS単体テストに加えMicrosoft Print to PDFの実機受入を必須にする |
| `afterprint`未発火や印刷キャンセル時の状態残留 | timeoutとtry/finally相当の復元経路、冪等なrestoreを用意する |
| 参照先監視数の増加 | 正規化済みtargetを重複排除し、タブ／ウィンドウ終了時に確実に解除する |
| プレゼンのキー競合 | フォーカス対象と処理済みイベントを判定する入力ルーターを単体テストする |
| 保存済み座標が無効または画面外 | 接続中モニターの作業領域へ補正し、既定サイズで復旧する |
| 追加起動が別プロセスになる | 単一起動プラグインで引数を既存プロセスへ転送し、生成処理を共通化する |
| VS Codeの既存ワークスペース指定 | フォルダとファイルを同時に渡す実機検証を必須にし、不足する場合は代替方式を設計レビューする |
| Ctrl+ホイールがページ操作と競合 | プレビュー内かつCtrl押下時だけ`preventDefault`し、10%刻みのテストを追加する |
