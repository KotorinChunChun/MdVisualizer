# MarkdownViewer v0.0.7-beta 配布実装計画

対応要求: [`v0.0.7-beta-req.md`](./v0.0.7-beta-req.md)
作成日: 2026-08-10 / ステータス: **公開・検証完了**
作業ブランチ: `feature/v0.0.7`

## Phase 1: 配布仕様の確定

- 要求、実装方針、進捗を文書化する。
- 数値バージョン、チャネルURI、Identity、Publisher、更新動作を固定する。
- Microsoft公式App Installer仕様とWeb配布要件を確認する。

## Phase 2: 署名・App Installer生成

- frontend、Tauri、Rustのバージョンを `0.0.7` へ統一する。
- 自己署名コード署名証明書をCurrentUserの証明書ストアに作成し、同じ証明書を再利用できるようMSIXビルドを拡張する。
- 証明書はFriendly NameとSubjectで厳密に識別し、期限、有効な秘密鍵、Code Signing EKUを検証する。
- 2021 App Installer schemaでbeta用ファイルを生成する。
- `OnLaunch HoursBetweenUpdateChecks="0" ShowPrompt="false" UpdateBlocksActivation="false"` とし、更新後の反映を次回起動に委ねる。
- App InstallerとMSIXのName、Publisher、Version、Architecture、URIの一致を自動検証する。

## Phase 3: 配布サイトと成果物

- MSIX、CER、App Installerを `www/download/beta` へ配置する。
- `/download/` に初回インストールページ、`/download/certificate/` に証明書導入手順を作成する。
- Apache互換のMIME設定を追加する。
- HTML、XML、リンク、署名、ハッシュ、成果物一覧をローカルで検証する。

## Phase 4: 公開と検証

- 既存FTPスクリプトのdry-runで対象が `www/download` 配下だけであることを確認する。
- 指定サーバーへFTPで公開する。
- 公開HTTPS URLへHEAD／GETを行い、status、Content-Type、Content-Length、リンク、App Installer内容を確認する。
- 実装・検証結果を報告書へ記録し、リリースタグ `v0.0.7-beta` を作成する。

## 既知の制約

- `ms-appinstaller:` URIプロトコルは多くの端末で既定無効のため、Webページは `.appinstaller` の通常ダウンロード／起動を主導線とする。
- 自己署名証明書は初回インストール前に各端末のCurrent User `TrustedPeople`へ登録する必要がある。
- betaと正式版は同じPackage Identityを使うため同時インストールできない。導入時に選んだApp Installer URIが更新チャネルになる。
- MSIXは数値4要素のVersionを要求するため、`v0.0.7-beta` のPackage Versionは `0.0.7.0` とする。
