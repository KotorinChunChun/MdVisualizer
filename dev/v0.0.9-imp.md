# v0.0.9 実装計画・報告

## 実装方針

- 表示用の文書内容と編集中のドラフトを分離し、保存成功時だけ保存済み状態を更新する。
- 「編集のみ」「編集／閲覧」「閲覧のみ」は、既存の文書レイアウト設定から独立したタブ単位の画面モードとする。
- Markdownの対象要素はソース位置と期待する元文字列で識別し、同一画像や同種フェンスの別出現を誤更新しない。
- ファイル書込みはRust側へ集約し、既存のロック、原子的置換、画像バックアップを再利用する。
- 参考HTMLの外部CDN依存をそのまま持ち込まず、エディターとパーサーはアプリへバンドルする。diagrams.netとの連携だけを明示的なオンライン機能とする。
- 各フェーズ終了時に関連テスト、コンパイル、本番ビルドを実行し、成功後に日本語コミットを作成する。

### 追加修正: ×ボタンで終了できない不具合

- `beforeunload`とTauriの`onCloseRequested`による二重の終了保護を廃止し、Tauri側の終了要求へ一本化した。終了要求はいったん抑止し、未保存変更がない場合または利用者が破棄を確認した場合だけ対象ウィンドウを明示的に破棄する。
- `onCloseRequested`の非同期登録がReact Strict Modeの再マウント後に残らないよう、登録完了前にクリーンアップされた場合も取得した解除関数を直ちに呼ぶようにした。
- 対象ウィンドウに必要な`core:window:allow-destroy`権限を追加した。未変更、未保存変更の破棄確認、終了キャンセルの3経路を単体テストへ追加した。
- Rustの`CloseRequested`中にネイティブウィンドウの位置・寸法を同期取得しないようにした。移動・サイズ変更イベントから最新値を保持し、破棄後に保持済み値を設定へ保存することで、終了イベント中の再入を防いだ。
- 人間入力を5.5秒間監視して入力がなかった場合だけ実画面を操作し、クリーン起動したMarkdownViewerの×ボタン操作後に対象ウィンドウが0件になることを確認した。

- MSIXやインストーラーは再生成せず、`tauri build --no-bundle`で生成したRelease exeをWindowsApps内の対象exeへ上書きする。
- WindowsApps内の操作は管理者権限へ分離し、対象単一ファイルの所有権とACLだけを一時変更する。更新前exeは`release/msix-debug-backup`へ退避し、SHA-256を照合して元のACL復元を試みる。
- この処理はMSIX署名の整合性を失わせるため、警告を表示して開発PCのデバッグ専用であることを明示する。
- 登録済みv0.0.8 MSIXを使った`-WhatIf`で対象exeを自動検出し、実ファイルのSHA-256が変化しないこと、登録パッケージ外のWindowsAppsパスを拒否することを専用PowerShellテストで確認した。

### 追加改善: SharePointサインインの長期保持

- `offline_access`で取得した更新トークンをメモリだけでなくWindows資格情報マネージャーへ保存し、アプリ再起動後もアクセストークンを自動更新する。
- Windows資格情報は現在のWindowsユーザーにより保護され、アクセストークンは従来どおりメモリだけに保持する。Microsoftからローテーションされた更新トークンは保存値へ反映する。
- アプリ側では保存期限を設けない。ただしMicrosoft側の失効、パスワード変更、管理者ポリシー、利用者による同意取消しの場合はデバイスコード認証へ戻る。
- 2026-08-13の再確認でインストール済みEXEが永続化実装前のビルドだったことを特定した。資格情報マネージャーの保存・再読込・ローテーションテストを再実行し、永続化実装を含むRelease EXEをWindowsApps内へ差し替えた。
- 初回サインイン後に資格情報エントリが生成され、アプリ終了・再起動後もエントリを保持したままSharePoint文書を開く復元経路を実機確認した。
- 管理者子プロセスが非0終了しても差し替え先とRelease EXEのSHA-256が一致する場合は、誤って失敗扱いにしないようデバッグ差し替えスクリプトを補強した。
- Credential Managerへの保存・読込み・ローテーション・削除テストを含むRust全87テストと`cargo check`が成功した。

### 追加フェーズ: spmd画像対応

#### フェーズ1: 認証付き画像読込み

- spmd Markdownの相対PNG／SVG参照を同じSharePointドライブ内のDriveItemへ解決する。
- Graphから取得した画像をアクセストークン非露出のData URIとしてフロントエンドへ渡し、PNG形式検証とSVG安全化を行う。
- 同一サイトかつMarkdownと同じドキュメントライブラリに解決できる相対参照だけを許可し、絶対URL、別サイト、クエリ、フラグメント、PNG／SVG以外を拒否した。
- 画像は50MiB以下に制限し、PNGはシグネチャ、IHDR、画素数上限をRust側で検証する。SVGはUTF-8とルート要素を検証し、フロントエンドで外部参照、スクリプト、イベント属性等を除去してからData URI化する。
- RustのSharePoint 9テスト、ImageRenderer 25テスト、TypeScript検査、Vite本番ビルドが成功した。

#### フェーズ2: 画像編集画面への接続

- spmd PNGを既存のラスタ画像編集画面へ読み込み、SVGは既存SVG編集経路へ接続する。
- ローカル画像専用のパス処理、ファイル監視、バックアップ処理と分離する。
- PNGは認証取得したData URIを既存の注釈、自由描画、切り抜き、回転、反転、サイズ変更等の編集画面へ渡し、ローカルファイル保存APIを呼ばずSharePoint保存用PNGを返す。
- SVGは安全化プレビュー付きソース編集画面を追加し、保存時にも安全化したXMLだけをSharePoint保存経路へ渡す。

#### フェーズ3: SharePoint画像保存

- GraphのDriveItem内容更新APIを使い、読込み時eTagを`If-Match`へ指定してPNG／SVGを元ファイルへ保存する。
- 競合、認証、形式、サイズ、ネットワーク障害時は元ファイルを変更せずエラーを返す。
- Microsoft Graph v1.0の小容量ファイル内容更新API（`PUT /drives/{drive-id}/items/{item-id}/content`）と委任`Files.ReadWrite`権限を使用する。更新前のメタデータeTag一致確認に加え、PUTにも`If-Match`を指定して412競合を上書きへ進めない。
- 保存先はRust側で再解決し、Markdownと同じサイトおよび同じドキュメントライブラリに限定する。PNG／SVGの50MiB上限と形式検証を再実行し、SVGはDOCTYPE、ENTITY、スクリプト、イベント属性、外部参照等も拒否する。
- SharePointの版履歴を利用するためローカル画像バックアップは作成しない。保存後は画像の取得バージョンを更新し、新しいeTag付きデータをGraphから再読込みする。
- RustのSharePoint 10テスト、PNG／SVG編集46テスト、`cargo check`、TypeScript検査、Vite本番ビルドが成功した。

#### フェーズ4: 統合確認

- 関連コンポーネントテスト、フロントエンド全テスト、TypeScript検査、Vite本番ビルド、Rust全テストを行う。

- MSIXとZIPは再生成せず、Tauri Release EXEだけを生成してインストール済みMSIX内へ差し替えた。生成物とWindowsApps内EXEのSHA-256 `15EFFE9F0282AEFC403DEE8748F6887A64707CE8F53061FCBC3FD73225A01485`が一致することを確認し、旧EXEを`release/msix-debug-backup`へ保存した。
- 画像保存用の委任`Files.ReadWrite`を追加したため、既存の保存済み更新トークンで拡張スコープを取得できない環境では一度だけ追加同意を要求する。取得後の更新トークンは従来と同じWindows資格情報へローテーション保存する。
