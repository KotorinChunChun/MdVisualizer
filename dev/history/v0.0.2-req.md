# 爆速 Markdown Viewer v0.0.2 要求定義書

* バージョン: `0.2.0`
* 作成日: 2026-07-28
* 作業ブランチ: `feature/v0.0.2`
* 対応実装計画: [`v0.0.2-imp.md`](./v0.0.2-imp.md)

## 1\. 概要

### 1.1 目的

本アプリケーションは、Markdownファイルの閲覧に特化した軽量・高速なデスクトップアプリケーションである。

Markdown編集機能は持たず、以下の体験を重視する。

* `.md` ファイルをダブルクリックして即座に開ける
* 大きなMarkdownファイルでも軽快に閲覧できる
* Mermaid、画像、表、コードブロックを快適に表示できる
* Chromeのようなタブ操作ができる
* Notionのように見出し単位で折りたたみ閲覧できる
* 画像をその場でクロップできる
* 編集が必要な場合は外部エディタに任せる

### 1.2 コンセプト

本アプリのコンセプトは以下とする。

> 上はChrome、本文はNotion、挙動はSumatraPDF、編集はVSCode任せ。

つまり、Markdownを「編集するアプリ」ではなく、Markdownを「爆速で読むためのビューアー」として設計する。

### 1.3 想定ユーザー

* Markdownで仕様書、メモ、README、設計書を管理しているユーザー
* VSCode等でMarkdownを編集し、閲覧専用の軽量ビューアーを求めるユーザー
* Mermaid図や画像を含む技術文書を日常的に確認するユーザー
* 複数Markdownファイルをタブで高速に切り替えたいユーザー

\---

## 2\. 基本方針

### 2.1 開発方針

* 起動速度を最優先する
* 閲覧体験を最優先する
* 編集機能は実装しない
* 日常操作は設定画面に入らず、画面上のツールバーで完結させる
* OS標準機能や外部エディタと自然に連携する
* 破壊的な画像編集操作については、アプリ起動中の復元手段を用意する
* 複数ウィンドウ・複数プロセスでも、監視対象や永続化データを互いに失わない設計とする
* 大規模文書を複数タブで開いた場合も、非アクティブタブのDOMを無制限に保持しない
* 非同期処理は世代番号またはキャンセルトークンで管理し、古い結果が新しい表示を上書きしない

### 2.2 実装しない機能

以下の機能は対象外とする。

* Markdownテキストの直接編集
* WYSIWYG編集
* 任意テキスト入力による文書作成
* ファイル管理機能
* Git連携
* 拡張機能システム
* AI連携
* Markdownの新規作成機能
* アプリ内での保存ダイアログによるMarkdown保存

## 4\. タブ機能

### 4.1 基本機能

ChromeライクなタブUIを提供する。

対応機能は以下とする。

* 複数Markdownファイルをタブで表示
* タブクリックによる表示切り替え
* タブの閉じるボタン
* タブ中央クリックで閉じる
* タブドラッグによる並び替え
* タブ右クリックメニューから別ウィンドウで開く
* 複数ウィンドウ起動
* 複数プロセス起動
* 同一ファイルの複数タブ表示

### 4.2 タブ情報表示

タブにマウスカーソルを当てた場合、ツールチップで対象ファイルのフルパスを表示する。

表示例:

```text
C:\\Project\\docs\\README.md
```

### 4.3 タブ右クリックメニュー

タブを右クリックした場合、以下のコンテキストメニューを表示する。

* ファイル名をコピー
* フルパスをコピー
* タブを閉じる
* 他のタブを閉じる
* 右側のタブを閉じる
* 別ウィンドウで開く
* VSCodeで開く
* メモ帳で開く

### 4.4 閉じたタブの復元

ショートカット:

```text
Ctrl + Shift + T
```

直前に閉じたファイルを再度開く。

要件:

* 閉じたタブ履歴を保持する
* 復元時は可能であれば前回のスクロール位置も復元する
* 履歴保持件数の初期値は50件とする

### 4.5 タブの状態保持とメモリ管理

非アクティブタブはMarkdown本文のDOMを常時保持せず、アクティブタブのみを本文ビューへマウントする。

タブごとに以下の論理状態を保持し、再表示時に復元する。

* ファイルパスと読込済みMarkdownデータ
* スクロール位置
* 折りたたみ状態
* 検索文字列、現在の一致位置
* 読込状態、エラー状態、更新あり状態
* Mermaid描画結果の状態

要件:

* タブ切り替え時に非アクティブタブの検索Range、Mermaid SVG、イベントリスナーを破棄する
* タブを閉じた後に遅延イベントや非同期結果が到着しても例外を発生させない
* 10,000行級の文書を複数タブで開いた場合に、タブ数に比例してDOMが無制限に増加しない

## 5\. ファイル起動・関連付け

### 5.1 ファイル関連付け

以下の拡張子を本アプリに関連付け可能とする。

* `.md`
* `.markdown`

ユーザーはMarkdownファイルをダブルクリックして本アプリで開ける。

### 5.2 コマンドライン起動

コマンドライン引数でファイルパスを受け取れること。

例:

```text
MarkdownViewer.exe C:\\Project\\README.md
```

### 5.3 フォルダを開くボタン

ツールバー上に「フォルダを開く」ボタンを配置する。

機能:

* 現在表示中Markdownファイルが存在するフォルダをOSのファイルエクスプローラーで開く
* 現在表示中ファイルが存在しない、または削除されている場合はエラー通知を表示する
* ボタンは常時表示し、設定画面に入らず使用できる

表示例:

```text
\[フォルダを開く]
```

### 5.4 任意ファイルを開くメニュー

本アプリには任意のMarkdownファイルを選択して開くための一般的な「ファイルを開く」メニューは持たせない。

基本導線は以下とする。

* `.md` ファイルの関連付けから開く
* コマンドライン引数で開く
* OS側の「プログラムから開く」で開く
* 既に開いているタブや履歴から復元する

## 6\. Markdown表示

### 6.1 対応Markdown

GitHub Flavored Markdown相当の表示に対応する。

対応要素:

* H1～H6見出し
* 段落
* 改行
* 箇条書き
* 番号付きリスト
* 引用
* コードブロック
* インラインコード
* 表
* チェックボックス
* リンク
* 画像
* 水平線
* HTMLの一部表示

### 6.2 Markdown内HTMLとサニタイズ

Markdown内HTMLは、許可した要素のみ表示し、必ずサニタイズする。

処理順は以下を基本とする。

1. MarkdownをGFMとして解析する
2. Markdown内の生HTMLをHTMLノードへ変換する
3. 見出し折りたたみ用のセクション構造を付与する
4. 最後に許可リスト方式でサニタイズする
5. サニタイズ済みの構造だけをReact要素として描画する

許可対象は、本文表示に必要な安全なタグと属性に限定する。

* 見出し、段落、リスト、表、引用、コード、強調等の基本要素
* `section`、折りたたみボタン、および実装が付与する限定的な `data-\*` 属性
* `language-\*`、`hljs-\*` 等、シンタックスハイライトに必要な限定的クラス
* 安全な `http` / `https` / `mailto` リンク
* 表示中Markdownを基準として解決した許可済みローカル画像

以下は除去または無効化する。

```html
<script></script>
<iframe></iframe>
<object></object>
<embed></embed>
```

追加要件:

* `onload`、`onclick` 等のイベント属性を許可しない
* `javascript:`、`vbscript:`、任意の `data:` URLをリンク先として許可しない
* `style` 属性は原則として許可しない
* 任意のクラス名や任意の `data-\*` を一括許可しない
* サニタイズ処理を通らないHTML挿入経路を作らない

## 7\. 本文ビュー

### 7.1 レイアウト

本文ビューは中央寄せとする。

ただし、本文最大幅は定義しない。ウィンドウを広げた場合、本文領域も可能な限り広げられるものとする。

要件:

* 本文は中央寄せ
* 最大幅制限なし
* 横幅の広い画面でも閲覧領域を広く使える
* 余白、行間、文字サイズは実際の見た目を確認しながら読みやすさを優先して調整する

### 7.2 行間

行間は固定値として厳密には定義しない。

以下を満たすように調整する。

* 長文が読みやすい
* 技術文書が詰まりすぎない
* 見出し、リスト、コードブロック、表の視認性が良い
* テーマごとに違和感が出ない

### 7.3 コードブロック

コードブロックは以下に対応する。

* 横スクロール
* シンタックスハイライト
* 右上にコピーボタンを表示
* コピー成功時にトースト通知を表示
* 長いコードでも本文レイアウトを崩さない

表示イメージ:

```text
+--------------------------------------------------------------+
| javascript                                            \[Copy] |
+--------------------------------------------------------------+
| const message = "Hello";                                    |
| console.log(message);                                        |
+--------------------------------------------------------------+
```

コピー対象はコード本文のみとし、言語名や行番号は含めない。

### 7.4 表

表は画面内の横幅に収める方向で表示する。

要件:

* 表は画面内の横幅で折り返して圧縮表示する
* 横スクロールではなく、可能な限り列幅調整と折り返しで表示する
* セル内テキストは折り返す
* 表全体が極端に崩れる場合は最低幅を設ける
* 表示が読みづらい場合に備え、将来的に横スクロール表示へ切り替える表示モードを追加可能にする

## 8\. 見出し折りたたみ機能

### 8.1 概要

H1～H6見出しに対して、Notionのようなトグル折りたたみ機能を実装する。

各見出しの左側に開閉アイコンを表示する。

* 展開状態: `▼`
* 折りたたみ状態: `▶`

表示例:

```text
▼ H1 要件定義
  本文...

  ▼ H2 機能要件
    本文...

    ▶ H3 Markdown表示
```

### 8.2 折りたたみ範囲

見出しを折りたたんだ場合、その見出し配下の本文、画像、表、コードブロック、下位見出しを非表示にする。

折りたたみ範囲は、次に現れる同階層以上の見出しの直前までとする。

例:

```markdown
## A
本文A
### A-1
本文A-1

## B
本文B
```

`## A` を折りたたんだ場合、以下を非表示にする。

```markdown
本文A
### A-1
本文A-1
```

`## B` は表示する。

### 8.3 全体開閉ショートカット

ショートカット:

```text
Alt + Ctrl + T
```

動作:

* 1つでも展開されている見出しがある場合は、全体を折りたたむ
* すべて折りたたまれている場合は、全体を展開する

### 8.4 折りたたみ操作コンボ

ツールバー上に折りたたみ操作用コンボボックスを配置する。

表示例:

```text
Fold:H2▼
```

候補:

* すべて展開
* すべて折りたたみ
* H1のみ展開
* H2まで展開
* H3まで展開
* 現在位置以外を折りたたみ
* 折りたたみ状態をリセット

### 8.5 折りたたみ状態の保持

以下を保持する。

* ファイル単位の折りたたみ状態
* リロード後の折りたたみ状態
* タブ切り替え後の折りたたみ状態

ただし、Markdown内容が大きく変更された場合は、可能な範囲で見出しテキストや階層をもとに復元する。

## 9\. ページ内検索

### 9.1 基本機能

ページ内検索を実装する。

ショートカット:

```text
Ctrl + F
```

検索UI:

```text
🔍 \[検索ワード................]  3/12  \[↑] \[↓] \[×]
```

### 9.2 検索仕様

* 入力中に即時検索する
* 一致箇所をハイライトする
* 現在選択中の一致箇所を強調表示する
* 一致件数と現在位置を表示する
* `Enter` で次の一致箇所へ移動する
* `Shift + Enter` で前の一致箇所へ移動する
* `Esc` で検索バーを閉じる

### 9.3 折りたたみと検索の連携

検索ヒットした見出し配下は一時的に自動展開する。

要件:

* 折りたたまれた範囲も検索対象に含める
* 検索ヒットが折りたたみ範囲内にある場合、その範囲を一時的に展開する
* 検索終了後は、検索前の折りたたみ状態に戻す
* 検索中にユーザーが手動で開閉した場合は、ユーザー操作を優先する

### 9.4 検索描画と互換性

検索ハイライトは、本文DOMをReactの管理外で恒久的に変更しない方式を優先する。

要件:

* CSS Custom Highlight APIを使用できる環境では、`Range` と `CSS.highlights` を使用する
* Highlight名はウィンドウIDとタブIDを含め、タブ間で衝突しないようにする
* 検索終了、タブ切り替え、タブ終了、再読込時に登録したHighlightを削除する
* APIが利用できない環境では、アプリが管理する一時的な `<mark data-search-owned>` によるフォールバックを使用する
* フォールバック要素は再描画前に必ず除去し、React管理DOMとの競合を残さない

## 10\. Mermaid対応

### 10.1 基本対応

Markdown内のMermaidコードブロックを図として描画する。

対応例:

* flowchart
* sequenceDiagram
* classDiagram
* stateDiagram
* erDiagram
* journey
* gantt

### 10.2 Mermaid操作UI

ツールバーにMermaid表示切り替えコンボを配置する。

表示例:

```text
Mermaid:ON▼
```

候補:

* ON
* OFF
* エラー時はコード表示
* 常にコード表示
* 図をクリックで拡大

### 10.3 エラー時表示

Mermaid描画に失敗した場合、以下を表示する。

* エラー概要
* エラー詳細表示ボタン
* Mermaidコード表示ボタン

### 10.4 Mermaidの安全性とライフサイクル

Mermaidは遅延ロードし、サイト全体の安全設定を一度だけ初期化する。

要件:

* `securityLevel: strict`、`startOnLoad: false` を使用する
* セキュリティに関係する設定を図側のfrontmatterやディレクティブで上書きできないようにする
* アプリテーマは、描画用の一時ソースにアプリ管理のfrontmatter設定を安全にマージして図単位で反映する
* ユーザーの元のMermaidコードは変更・保存しない
* Mermaid描画IDはウィンドウID、タブID、ブロックIDを含む一意な値にする
* 描画処理は直列化または世代管理し、古い描画結果を現在のタブへ反映しない
* タブ切り替えまたは破棄後に完了した描画結果は無視する
* 図の数、テキスト量、辺数に上限を設け、極端な入力でUIを長時間停止させない

## 11\. 画像表示・画像編集

### 11.1 画像表示

Markdown内の画像を表示する。

対応パス:

* 相対パス
* 絶対パス
* 同一フォルダ内画像
* サブフォルダ内画像

### 11.2 画像編集モード

画像をクリックした場合、画像編集モードに切り替える。

画像編集モードでは、対象画像にクロップ用の枠とハンドルを表示する。

操作対象:

* 四隅
* 上辺
* 下辺
* 左辺
* 右辺

### 11.3 クロップ操作

* 四隅ドラッグで縦横同時にクロップ範囲を変更する
* 辺ドラッグで一方向にクロップ範囲を変更する
* ドラッグ中はリアルタイムにプレビューする
* `Enter` で確定保存する
* `Esc` でキャンセルする

### 11.4 保存

クロップ確定時、即座に画像ファイルを更新する。

保存後はMarkdownビューを再描画し、更新後の画像を表示する。

### 11.5 一時バックアップと復元

破壊的編集に備え、アプリ起動中は一時フォルダに対象画像のバックアップを保存する。

要件:

* 初回編集前に元画像を一時フォルダへ保存する
* アプリ起動中は元に戻す操作に対応する
* 画像単位で復元できる
* アプリ終了時に一時ファイルを削除する
* 将来的に一時バックアップ保持モードを追加可能にする

### 11.6 通知

画像更新時はトースト通知を表示する。

表示例:

```text
image.png を更新しました  \[元に戻す]
```

## 12\. 自動更新・リロード

### 12.1 F5リロード

ショートカット:

```text
F5
```

現在表示中のMarkdownファイルを再読み込みする。

### 12.2 自動リロード

Markdownファイルの変更を検知し、自動的に再読み込みする。

監視対象:

* 各ウィンドウで開いているMarkdownファイル
* 各Markdownから参照されているローカル画像ファイル

複数ウィンドウ対応要件:

* ウィンドウごとに監視対象集合を管理する
* Rust側は全ウィンドウの監視対象の和集合だけを実際に監視する
* あるウィンドウが監視対象を同期しても、別ウィンドウの監視対象を解除しない
* ウィンドウ終了時は、そのウィンドウが所有していた監視対象だけを登録解除する
* パスは正規化・絶対化して比較し、同一ファイルの重複監視を防ぐ
* 変更イベントは正規化済みパスと変更種別を含めて通知する
* 短時間の変更はパス別にまとめ、別ファイルの変更イベントを相互に消さない
* ファイル削除、リネーム、保存時の一時ファイル置換を扱う

### 12.3 自動リロードUI

ツールバーに自動リロード切り替えコンボを配置する。

表示例:

```text
AutoReload:ON▼
```

候補:

* ON
* OFF
* 手動のみ

### 12.4 リロード時の保持情報

リロード時は以下を可能な限り保持する。

* スクロール位置
* 折りたたみ状態
* ズーム率
* 検索状態
* 選択中タブ

### 12.5 再読込の整合性

ファイル読込は非同期処理として世代管理する。

要件:

* タブごとに読込世代番号またはキャンセルトークンを持つ

* 連続保存時は最終的なファイル内容へ収束する
* タブを閉じた後の読込完了結果は破棄する

## 19\. 非機能要件

### 19.1 起動性能

最重要要件として、起動速度を最優先する。

目標:

* 通常起動: 300ms以下
* 理想値: 100ms以下
* ファイル関連付け起動時も体感的に即時表示されること

### 19.2 メモリ使用量

目標:

* 初期起動時: 100MB以下
* 理想値: 50MB以下

### 19.3 描画性能

* 10,000行超のMarkdownでも快適にスクロールできること
* スクロール中の引っかかりを最小化すること
* Mermaidや画像を含む場合も段階的描画により初期表示を妨げないこと

### 19.4 安定性

* 本バージョンでは異常終了時のタブ一覧復元は行わない。詳細はQA#4に従う
* ファイル削除、移動、アクセス権不足時にクラッシュしない
* Mermaid描画エラー、画像読み込みエラー、文字コード判定失敗時にクラッシュしない
* 設定ファイルまたは折りたたみ状態ファイルが破損していても、退避して既定値で起動できる
* タブ終了後のファイル監視イベント、読込完了、Mermaid描画完了を安全に破棄できる
* 複数ウィンドウで異なるファイルを同時保存しても、双方の更新を検知する
* 同じ画像を複数プロセスから同時に変更しようとした場合は競合を検出し、無条件に後勝ち上書きしない

### 19.5 セキュリティ

* Markdown内HTMLは許可リスト方式でサニタイズする
* 外部リンクを開く場合は `http` / `https` / 必要な `mailto` のみをOS既定ブラウザへ渡す
* ローカルファイル参照は表示中Markdownから解決した正規化済みパスを基本とする
* WebView内で外部ページへ遷移しない
* 不正なスクリプト、イベント属性、危険なURLスキームを許可しない
* Tauri capabilityは `main` と規則化した動的ウィンドウラベルだけを対象にし、必要最小限の権限を付与する

### 19.6 永続化とデータ整合性

設定と折りたたみ状態は、複数プロセスから安全に更新できること。

要件:

* 保存ファイルに `schemaVersion` を持たせる
* 保存時はOSレベルの排他ロックを取得する
* ロック取得後に最新ファイルを再読込し、変更対象キーだけをマージする
* 一時ファイルへ書き込み、flush後に原子的に置換する
* 一時ファイル名はプロセスごとに一意にする
* ロック待機にはタイムアウトを設け、失敗時はエラー通知して既存ファイルを壊さない
* JSON破損時は破損ファイルを日時付きで退避し、既定値から再生成する
* 複数プロセスが別ファイルの折りたたみ状態を更新しても、互いのキーを消失させない

### 19.7 性能測定条件

性能値はリリースビルドで測定する。

* 測定PC、OS、WebView2バージョン、CPU、メモリを記録する
* 起動時間はプロセス開始から最初の本文表示完了までとする
* 同一条件で5回以上測定し、中央値と最大値を記録する
* メモリは初期表示安定後と、10,000行文書を10タブ開いた状態の両方を測定する
* スクロール性能は長文、表、画像、Mermaidを含むサンプルで確認する
* 要求値を満たせない場合は、リリース前に原因と対応方針を記録する

## 22\. まとめ

本アプリは、Markdownの編集機能をあえて持たないことで、起動速度と閲覧体験に特化したMarkdownビューアーを目指す。

特に以下を主要価値とする。

* `.md` を即座に開ける爆速起動
* Chromeライクなタブ操作
* Notion風のH1～H6折りたたみ
* Mermaid対応
* 画面内コンボによる設定画面レスな操作
* コード、表、画像を含む技術文書の快適な閲覧
* 画像クロップ編集と一時復元
* 外部エディタとの自然な連携

本アプリの位置づけは、Markdownエディタではなく、Markdownドキュメントを高速に閲覧するための専用ブラウザである。

* 上部の見出し操作は「折りたたみ」の文字を表示しない。コンボは現在状態を表すものではなく一時操作のため、選択後に「操作を選択」へ戻す
* VS Code起動時にコマンドプロンプトを表示しない
* SVG画像は表示と監視に対応するが、クロップ・表示リサイズの編集対象にはしない
* ページ内検索はハイライトを維持し、前後移動時に対象位置へスクロールする
* 再読込後は既存の折りたたみ状態と保存済みスクロール量を復元する
* `samples/` をGit管理対象にし、総合記法、Mermaid、画像、ローカルリンクの確認資料を置く

以下は設計影響が大きいため v0.0.3 へ移し、人間レビュー完了まで実装しない。

* 編集で前段の行数が変わっても同じ文字を追跡する意味的スクロールアンカー
* 任意の外部アプリ登録を扱う設定画面
* 見出し階層、パンくず、ページ送りを持つプレゼンモード
