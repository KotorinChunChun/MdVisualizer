## 目的と構成

デスクトップ版の配置を基にした単一の `shell.tsx` から、環境プロファイルに応じてデスクトップ・Web・SPFx向けの外見を生成する。生成器は同じJavaScript・CSSを3ファイルへ埋め込み、初期環境だけを変更する。画面上でも環境を切り替えられる。

- 製品の `WorkspaceViewControls`、`StatusBar`、`DocumentSidePanel` を直接利用する。
- 共通正本の `app.css`、`content.css`、`themes.css` を利用する。
- タブの外枠、文書操作列はデスクトップの配置を参考に試作用として組み立てた。`App.tsx` 全体を自動解析・変換する実装ではない。
- 環境差は `profiles` に集約。OS機能・AI・再読込の表示を切り替える。ここでの能力設定は提案であり、各製品の対応機能を確定するものではない。
- 編集領域とプレビュー本文・図・ブロックメニューは固定サンプル。製品のMarkdownエディター／レンダラーや全メニューを移植したものではない。
- OS・認証・ファイル保存・SharePointへの接続、外部通信、利用者設定の書き換えは行わない。未接続の操作は案内を表示する。
- 画面幅・テーマ・コード／ビジュアル・分割方向・目次等・AI欄・閲覧権限の切り替えは試作内で動作する。

## 属性方式の統合マスター（追加試作）

ユーザー指示に基づき、デスクトップを唯一の上位UIとせず、Web・SPFx固有操作を含むマスターを作成した。従来試作を残し、追加した `master-template.html` をマスター正本とする。

```html
<button data-platforms="desktop web spfx" data-action="document.save" data-write>保存</button>
<button data-platforms="web" data-action="web.zip" data-write>ZIPを保存</button>
<button data-platforms="spfx" data-action="spfx.files">ファイル一覧</button>
```

- `data-platforms`: desktop / web / spfx の空白区切り。未指定なら親の対象範囲を継承し、親にも指定がなければ全環境。
- `data-capability="php"`: WebのPHP保管が利用可能な場合だけ描画する。統合マスター表示では含める。
- `data-formats`: 選択したブロック形式に適合する操作だけ描画する。
- `data-write`: 閲覧権限のみの場合は無効化する。実製品への移行時には実行処理でも権限検査が必要。
- `data-action`: 環境別の処理を接続するための操作ID。現段階は模擬操作のみ。
- `data-group`: 対象外の操作を除いたあとに空になったグループを除去する。

未接続のtemplate断片を複製し、属性で除去したあとにDOMへ取り付ける。表示後のCSS隠蔽ではない。統合マスターでは全環境を表示し、対象属性を注記する。切替用のマスター定義自体はHTML内に残るため、環境別コードのビルド除外や機密情報の保護を行う仕組みではない。

対象は文書操作、タブ、表示切替、書式17操作、コード／プレビュー、ステータス、ブロック形式別メニュー、編集ダイアログ見本、Web保存・下書き・PHP保管、SPFx接続設定、デスクトップ設定・AI・外部連携。配置は提案を含み、SPFxのWebパーツ設定も比較用に同じページへ展示している。既存製品と完全一致する画面の自動変換ではない。

生成時に既存のUI抽出器でソースを走査し、1,114件の全操作目録を取り込んだ。動的名称とソース位置も保持する。全操作目録は漏れの照合用であり、全1,114操作の画面移植・機能実装やプラットフォーム別の動作保証を意味しない。
