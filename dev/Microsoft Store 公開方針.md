# Microsoft Store 公開方針

本アプリは、Windows専用アプリとして **Microsoft Storeで一般公開することを前提** に開発してください。

公開方式については、以下を正式方針とします。

- Microsoft Partner Center は **Individual（個人）開発者アカウント** を使用する。
- Microsoftには本人確認を行うが、一般ユーザーに個人の本名を積極的に公開しない方針とする。
- Store上では、可能な範囲で **ブランド名／Publisher Display Name** を使用する。
- アプリの配布形式は **MSIX** を正式なリリース形式とする。
- Microsoft Store経由の配布を基本とし、Store公開版について独自の有料コード署名証明書を前提としない。
- Microsoft Storeによる署名・配布フローに適合する構成にする。
- 開発中に必要なテスト用署名と、Microsoft Store公開時の署名・Package Identityを混同しないこと。

## MSIX設計上の注意

MSIXの以下の値は、Microsoft Partner Centerでアプリ登録後に取得する正式な値へ差し替えられる設計にしてください。

- Package Identity Name
- Publisher
- Publisher Display Name
- Package/Identity関連情報
- Store側で必要となるその他の識別情報

現時点で正式値が決まっていない場合は、コードやビルド設定へ不必要に固定せず、後から安全に変更できる構成にしてください。

特に、仮の自己署名証明書に含まれるPublisher情報を、そのまま本番用のIdentityとして設計しないでください。

## プライバシー方針

一般公開される情報については、可能な限り個人情報を分離してください。

以下をソースコード、MSIX設定、About画面、ログ、設定ファイル等へ不用意に埋め込まないでください。

- 開発者の本名
- 個人住所
- 個人電話番号
- 個人用メールアドレス
- Windowsユーザー名
- ローカルPC固有のパス
- その他、開発者個人を特定できる情報

アプリ内で開発者・発行元を表示する必要がある場合は、原則としてブランド名を使用してください。

## 開発・ビルド方針

以下を満たす構成にしてください。

1. 通常のDebugビルド
2. Releaseビルド
3. MSIXパッケージ生成
4. ローカルでのMSIXインストールテスト
5. Microsoft Store提出用パッケージ生成

これらを可能な限り再現可能なビルド手順にしてください。

可能であれば、

- Visual Studio
- CLI
- PowerShell
- CI/CD

のいずれからでもMSIXを生成しやすい構成にしてください。

## Microsoft Store対応

実装する機能や使用するAPIについても、Microsoft Storeへの公開を阻害しないことを前提に判断してください。

特に、

- 管理者権限
- Windowsサービス
- ドライバー
- レジストリ操作
- ファイルシステムへの特殊なアクセス
- 外部プロセス実行
- ネットワーク通信
- 自動アップデート
- ライセンス管理

などを実装する場合は、Microsoft Store/MSIXとの互換性に問題がないか考慮してください。

Store公開に支障が出る可能性がある設計を採用する場合は、実装前にその理由と代替案を提示してください。

## 更新方式

Microsoft Store公開後の通常アップデートは、基本的に **Microsoft Store経由** とします。

独自アップデーターを標準機能として実装する必要はありません。

バージョン番号については、Microsoft Store/MSIXで継続的に更新できるよう管理してください。

## 最重要方針

このプロジェクトでは、

**「個人開発者であることを一般ユーザーに必要以上に露出させず、ブランド名でMicrosoft Storeに公開できる、正式なMSIX Windowsアプリ」**

を目標とします。

以後、ビルド方式、署名方式、Package Identity、アップデート方式、インストール方式などについて技術判断を行う際は、この方針を前提にしてください。
