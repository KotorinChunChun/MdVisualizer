# UI設計と編集状態

本書は画面を変更するときに維持する操作の意味と設計観点をまとめる。AI操作は[AI利用仕様](/docs/user/ui/codex.md)、比較・採用・保存は[Diff仕様](/docs/developer/testing/04-document-diff.md)を併読する。

## コード編集画面の表示状態

保存・再読込・同じ文書の再表示では、アプリを開いている間の縦横スクロール・選択範囲・折畳をファイルパス単位で復元する。本文変更と重なる折畳は安全のため展開する。アプリ再起動後は既定の折畳を適用する。

コードブロックは本文10行以上を初期状態および「折畳」で折りたたみ、設定で1〜100000行へ変更できる。Base64は行数によらず折りたたむ。「折畳」はH2以下を対象とし、H1を新しく折りたたまない。

## 情報の配置と操作の意味

- 文書名、未保存状態、表示モード、保存操作を見分けられる構成にする。文書本文を主要領域とし、低頻度の操作で圧迫しない。
- 表・画像・Mermaid・draw.ioへの操作は対象との関係が分かる位置に置く。選択対象、新規AI会話、現在の会話への添付を混同させない。
- 保存、外部更新、競合、AI提案の採用は別の状態として表示する。提案の採用はドラフト更新であり、保存完了とは表示しない。
- 重要な競合・エラーは一時通知だけにせず、解決まで再確認できるようにする。色だけに頼らず文言とアイコンを併用する。
- パネルの拡大・復元やタブ切替で会話、入力、添付、文書の未保存内容を失わせない。

## キーボード・表示の設計観点

標準のbutton/input/selectを優先する。ボタンは共通CSSを使用し、文書ツールバーにはdocument-action-buttonを使う。hover、focus、disabled、選択中を揃え、個別のインラインstyleで共通状態を上書きしない。

Tab順は読み順に揃え、正のtabIndexで補正しない。モーダルは初期フォーカス、内部の移動、Esc、閉じた後の起点復帰を確認する。アイコンだけの操作には名前を付け、画像ALTや図の意味を保つ。ショートカットの表示と実際のキー操作を一致させる。

ビジュアル編集で移動可能な本文をマウス左ボタンで押した時点で、対象ブロックへ移動対象の枠を表示する。マウス移動を待たず表示するが、ドラッグ開始は従来どおり5px以上の移動後とする。クリックのみでは本文を移動しない。押下終了・取消時は表示を解除し、リンク・編集入力欄等の操作を妨げない。

MarkdownコードビューのTSVフェンス本文内では、Tabでカーソル位置へ実タブ文字を挿入する。選択範囲がある場合はタブ文字に置換し、Undoで戻せる。開始・終了フェンス行、他言語のコードブロック、通常本文では従来のインデント処理を維持する。Shift+Tabの動作は変更しない。

明暗テーマ、狭幅、200%拡大で保存・取消・エラーの導線が隠れないか確認する。横長の表は表の内部でスクロールさせ、ページ全体の不要な横スクロールを避ける。これらは変更時の設計・検証観点であり、すべての環境で受入済みという意味ではない。

## 表示形式と編集状態の独立性

目次・ソース位置へのジャンプは本文コンテナー内だけをスクロールする。外側の画面を動かす`scrollIntoView`を使用せず、CSS zoomを考慮した本文内の座標に変換する。文末の見出しを画面上端へ合わせられない場合は末尾で止め、位置合わせのための余白は追加しない。

- `editorMode`はコード／コード＆ビジュアル／ビジュアルの配置を選ぶ。`interactionMode`は閲覧／編集の操作状態を選ぶ。ビジュアル編集のフラグ`visualEditing`は`interactionMode === "edit"`であり、単独ビジュアル表示だけに限定しない。
- デスクトップでは同じ文書・世代のCodeMirrorをビジュアル表示中も非表示で保持し、コード・ビジュアルの変更を共通のUndo履歴へ入れる。ビジュアル側のCtrl+Z／Ctrl+Shift+Zもその履歴を使用する。入力欄内の未確定編集は入力欄自身のUndoを使用する。別文書・世代への切替はこの履歴維持契約の対象外。
- 表示形式を切り替える直前の表示中央に対応するソース行を取得し、切替後の表示へ引き継ぐ。ピクセル位置の一致ではなく、対応する本文位置を基準とする。
- ビジュアル編集中の本文クリックはコードへフォーカスを移さない。Markdownの強制改行後は、変換後のテキスト開始位置が消失する場合に直前の改行終端から元ソースの編集位置を復元する。
- Markdown表のビジュアル編集ではセルクリックで行を選択し、本文行をドラッグして並べ替える。ヘッダー行は本文行の並べ替え対象にしない。セル本文のダブルクリックは直接テキスト編集、空セル・余白のダブルクリックは表編集画面を開く。閲覧時の範囲選択は維持する。
- `Footnotes`はMarkdownの脚注参照・定義から変換ライブラリが生成する脚注一覧見出しであり、Markdownへ追記されたH2ではない。ライブラリ既定は`h2`、見出し文字列は`Footnotes`である。

## 選択色と差分色の共通定義

正本は共有UIの `styles/selection-state.css`。色の意味をコンポーネントごとに再定義せず、通常コード・ビジュアル・差分で同じCSS変数を参照する。青はテーマのアクセント色と本文下地の混色であり、透明な選択背景を重ねて濃くしない。

| 番号 | 色・トークン | 適用状態 |
| --- | --- | --- |
| 01 | 青10% `--selection-current-bg` ＋濃青左線 `--selection-current-edge` | 通常コードの現在行、対応するビジュアルブロック、差分の現在行。クリック・キー移動に追従 |
| 02 | 01と同じ青10% | ビジュアルの移動可能ブロックのホバー・押下対象。押下の輪郭は別に維持 |
| 03 | 青28% `--selection-range-bg` | 通常／差分コードとビジュアル本文の文字選択、表の行・セル、表編集の選択入力欄 |
| 04 | 既存の青20%・枠・太字 | 目次の現在位置。変更しない |
| 05 | 黄 `#fbbf24`、文字 `#111827` | 検索一致。変更しない |
| 06・09 | 薄赤 `--diff-delete-bg`、濃赤 `--diff-delete-word` | 差分の旧内容・削除行と削除文字。−記号を併用 |
| 06・08 | 薄緑 `--diff-add-bg`、濃緑 `--diff-add-word` | 差分の新内容・追加行と追加文字。＋記号を併用 |
| 07・11 | 01の青10%＋青線、文字差分の赤緑は残す | 現在行と差分が重なる場合。文字範囲選択中は03を文字上に優先 |
| 10 | 06・08・09と同じ赤緑 | 左右分割の差分。変更専用のオレンジは使わない |

ライトテーマでは追加行 `#e6ffec`／追加文字 `#abf2bc`、削除行 `#ffebe9`／削除文字 `#ffcecb`。ダーク系は緑 `#2ea043` の15%／40%、赤 `#f85149` の10%／40%を本文下地に混色する。これは承認済みのGitHub型配色であり、GitHubの画面全体を再現するものではない。

コードの文字選択には共通の選択Decorationも使用し、不透明な現在行・差分背景に選択レイヤーが隠れないようにする。印刷時は現在位置・移動対象・範囲選択の操作用装飾を抑制する。TOC・検索・差分の意味トークンとは独立して扱う。

差分ボタンは `data-ui-command="document.diff"`、`aria-pressed` を状態の契約とし、選択時は他のモードと同じ青背景・白文字で表示する。汎用ボタンの規則より優先される共通セレクターを維持する。差分内部の分割は左右固定で方向プルダウンを設けない。「1画面／分割」は残す。本文のコード＆ビジュアル用の分割方向は別機能として維持する。

## 未採用の画面構成案

開始画面の最近使った文書、設定検索、コマンド検索、同期パネル、SPFxモバイル用drawerなどは[UI構成の設計案](/docs/developer/ui/workspace-design.md)にまとめる。図やコンポーネント名は設計案であり、現在の実装を保証しない。現行操作と案の違いを確認してから採用を判断する。
