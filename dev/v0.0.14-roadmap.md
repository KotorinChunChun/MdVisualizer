# MarkdownViewer v0.0.14基準 製品ロードマップ

作成日: 2026-08-30
状態: IN_PROGRESS

## 1. 製品ビジョン

WindowsデスクトップとSharePoint SPFxを同格の提供面とし、Markdownを正本のまま、安全に閲覧・編集・同期・AI支援できるOSS文書ワークベンチを目指す。機能数ではなく「既存ファイルを壊さない」「送信先と変更内容を利用者が把握できる」「小型AIモデルでも一工程を実装できる」ことを差別化軸にする。

## 2. ロードマップ原則

1. ローカルMarkdown／SharePointファイルを正本とし、独自DBへ本文を囲い込まない。
2. デスクトップとSPFxは共通ドメイン契約を持ち、OS能力差は能力マトリクスで明示する。
3. AIや同期より先に、アーキテクチャ境界、CSP、テスト、補助DBを整える。
4. AI変更は必ず一時差分を生成し、ファイル単位の利用者承認後に保存する。
5. 新規外部プラグインは導入せず、内部プロバイダーインターフェースだけを整備する。

### v0.0.14で実装しないもの

- 本番SharePointバックグラウンド同期
- 本番AI API／Claude CLI／Codex CLI接続
- 外部プラグイン読み込み
- macOS／Linux、PWA、ネイティブモバイル

これらのインターフェースとテスト用fakeまでは作成し、次版の変更量を小さくする。

## 4. v0.0.15〜v0.0.16

### v0.0.15 SharePoint同期

- SQLite同期キュー、対象文書、eTag、再試行時刻、競合状態を実装する。
- バックグラウンド取得は明示的に開いたSharePoint文書または利用者が同期対象へ追加した文書だけに限定する。
- 自動マージは行わず、差分画面で「ローカル案／SharePoint最新版」を利用者が選ぶ。
- SPFxはSharePointを直接正本として使い、デスクトップとの共通同期状態モデルとエラー語彙だけを共有する。

### v0.0.16 AI支援

- APIキー型プロバイダーとCLI型プロバイダーを同じストリーミング契約へ接続する。
- 校正、要約、質問、構成提案、Markdown／表／図表生成、診断、複数文書検索、直接編集案を段階導入する。
- 直接編集は一時パッチを作り、既存Diff UIでファイル単位に承認する。
- APIキーはデスクトップOS資格情報ストアへ保存する。SPFxへブラウザー保存APIキーは実装しない。SPFx AIは安全な組織管理エンドポイントが定義された場合に別設計とする。

### v0.0.15〜v0.0.16の品質目標

- 主要ドメイン行カバレッジ85%以上、分岐80%以上。
- 同期・AIの失敗系をfake clock、fake provider、SQLite一時DBで完全自動化する。
- 10,000行文書の検索p95 200ms以下、入力応答INP相当200ms以下を目標とする。

## 5. v0.0.17〜v0.0.19（将来版）

### v0.0.17〜v0.0.19

- SPFxモバイルの閲覧・簡易編集をWCAG 2.2 AA相当で仕上げる。
- 大規模文書の段階描画、図表のオンデマンドロード、検索索引を最適化する。
- AIプロバイダーの能力ネゴシエーション、費用上限、コンテキスト縮約、監査可能な実行履歴を追加する。
- 同期対象とAI対象を管理する統一「文書権限・送信先」画面を追加する。
- OSS運用としてSECURITY.md、CONTRIBUTING.md、CODE_OF_CONDUCT.md、第三者ライセンス生成を整備する。

### v1.0判断ゲート

- デスクトップとSPFxの共通受入契約が安定している。
- 2リリース連続で重大なデータ損失・権限逸脱がない。
- 更新・移行・ロールバック手順が自動検証されている。
- 主要機能のE2E、アクセシビリティ、性能、セキュリティ基準がCIで判定される。
