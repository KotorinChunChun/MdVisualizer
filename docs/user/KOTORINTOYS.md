# KotorinToysから使う

コレクションでMdVisualizerを選び「起動」を押すと画面を開く。既に起動しているときは同じプロセスの画面を復元する。「停止」は全ウィンドウに正常終了を依頼する。未保存文書、保存中、読込中、編集ダイアログがある場合は拒否する。作業を完了して再試行する。

常駐・通知領域・自動起動は使用しない。最後のウィンドウを閉じるとプロセスも終了する。KotorinToys 0.1.16以降は、GitHubで公開された署名付きMSIXの導入・更新・削除に対応する。現在のKotorinToysを先に更新し、「状態を更新」で一覧を読み込む。

MSIXは既存の`com.mdvisualizer.viewer`の識別子を維持する。署名をWindowsが信頼できない場合は導入が失敗する。証明書の信頼登録は別操作であり、本体は自動登録しない。既存のMdVisualizerが管理終了に対応していない場合や未保存文書がある場合は、作業を保存して通常の終了を行ってから更新する。

## 引数

- `mdvisualizer.exe [文書 ...]`：通常起動。関連付けからの文書起動も維持する。
- `--launch-origin standalone|host_manual`：起動経路を管理状態に表示する。省略時はstandalone。
- `--settings-dir <フォルダー>`：設定・AI関連データ・WebView2プロファイル・単一起動識別子・管理窓口を分離する。開発試験用。通常は指定しない。
- `--help`：引数を表示して終了する。
- `--startup`と`--hidden`、自動起動用の経路は終了コード2で拒否する。

管理窓口は`KotorinToys.<現在ユーザーSID>.md-visualizer`。管理契約2の`status/show/stop`を提供し、操作には対象PIDが必要。別セッション、誤PID、応答期限超過は操作しない。本文や認証情報は返さない。

正式MSIXでは、この名前の末尾にPackage FamilyのSHA-256（小文字64桁）を付け、本体側のMSIX識別と照合する。表示・管理応答はMSIXと同じ4成分版を使う。

隔離設定時は、絶対設定パスを小文字・Windows区切りへ正規化したSHA-256先頭16桁を管理窓口の末尾へ付ける。同じ設定先への再起動は同じ窓口となり、通常版とは別プロセスになる。

開発者向けの検証手順は[管理連携試験](../developer/testing/07-kotorintoys-integration.md)を参照する。
