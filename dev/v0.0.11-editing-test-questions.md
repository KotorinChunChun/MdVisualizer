# Markdown編集テストの質問事項と暫定想定

作成日: 2026-08-24

この文書は、仕様が明示されていない編集挙動を質問事項として残し、回答を待たずにテストを進めるための暫定想定を記録する。回答を受けた場合はケースの期待値を更新する。

| No. | 質問事項 | 今回の暫定想定 |
| ---: | --- | --- |
| 1 | IME変換中の未確定文字列も`onChange`対象とするか。 | 変換途中は保存対象の確定編集として扱わず、確定文字列だけを通常入力ケースで検証する。 |
| 2 | 通常行でTabを押した場合、フォーカス移動とインデントのどちらを優先するか。 | 現在の`indentWithTab`設定に従い、エディター内のインデントを優先する。 |
| 3 | 通常の引用行でEnterを押した場合、次行へ`> `を自動継続するか。 | アプリ独自仕様ではなくCodeMirror Markdown標準動作に従う。独自リスト継続だけを固定仕様として扱う。 |
| 4 | `(`、`[`、バッククォート等の括弧・記号を自動で閉じるか。 | CodeMirror標準設定の挙動に従い、アプリ独自の自動補完仕様とはしない。 |
| 5 | 選択なしのCtrl+Xで現在行全体を切り取るか。 | ブラウザー／CodeMirror依存として保留し、今回は明示選択した範囲の切り取りだけを固定期待値にする。 |
| 6 | 文字入力と直後の自動再採番はUndo一回で同時に戻すか。 | 利用者から見て一操作なので同時に戻ることが望ましいが、今回はCodeMirror履歴単体と再採番純粋関数を分けて検証する。 |
| 7 | 連続文字入力をUndo一回でどこまでまとめるか。 | CodeMirrorの履歴グループ規則に従う。明示的な単一トランザクションのUndo／Redoを固定検証する。 |
| 8 | 文書末尾の改行を編集・保存時に自動追加または削除するか。 | 自動変更せず、入力に存在する末尾改行の有無を保持する。 |
| 9 | LFとCRLFが混在する文書へ改行を挿入するとき、どちらを使うか。 | 現行実装と同じく、文書内にCRLFが一つでもあればCRLFを優先する。 |
| 10 | リストの1階層を2空白、4空白、タブのどれに統一するか。 | エディター操作で追加する階層は2空白とし、貼り付け済みの4空白・タブは破壊せず保持する。 |
| 11 | 番号付きリストを貼り付けた際、入力番号を保持するか。 | 現行仕様どおり階層ごとに1から再採番する。`.`と`)`の記号は保持する。 |
| 12 | 見出しを異なる親または異なるレベルへドラッグした場合に階層を変換するか。 | 変換せず移動不可とする。同一親・同一レベル間だけを入れ替える。 |
| 13 | Setext見出しを見出し入れ替え対象に含めるか。 | 現在の見出し解析がATX形式のみのため、Setextは通常行として扱う。 |
| 14 | 見出し移動時、直後の空行、本文、子見出し、コードフェンスをどこまで伴うか。 | 次の同レベル以上の見出し直前までを一つのセクションとして移動する。 |
| 15 | 複数カーソル編集を正式対応するか。 | 現在のアプリ独自キーマップが主選択だけを参照するため、今回の固定ケースは単一選択とする。 |
| 16 | クリップボードにHTMLとplain textが同時にある場合、どちらを貼り付けるか。 | 画像以外はplain textを使用する。HTMLをMarkdownへ自動変換しない。 |
| 17 | BOM、NUL、双方向制御文字を削除・正規化するか。 | 編集レイヤーでは自動除去せず文字として保持する。安全性判断は表示・保存レイヤーの責務とする。 |
| 18 | 非常に大きい選択範囲や貼り付けサイズに上限を設けるか。 | 現時点では上限を設けず、純粋関数で1万文字級の境界ケースを検証する。 |
| 19 | 切り取り範囲内を貼り付け先に指定した場合の扱いはどうするか。 | 元の選択開始位置へ戻すものとしてテキストを変更しない。 |
| 20 | 空選択の切り取り貼り付けをどう扱うか。 | 変更なしとする。 |

## 今回追加する想定テスト

- 単一編集のUndoとUndo後のRedo。
- BOM、NUL、RTL、双方向制御、補助漢字、複合絵文字を含む入力・削除・置換。
- 末尾改行あり／なし、混在改行、空文書、1万文字級文書の境界編集。
- 切り取り先が前方・後方・選択範囲内・空選択の場合。
- ATX見出しの閉じ記号、重複名、子見出し、コードフェンス、異なる親・レベルの移動可否。
- `-`、`+`、`*`、`.`、`)`、タスク、タブ、2／4／6空白を混在させたリスト編集。

## 暫定想定での実行結果

- 上記想定に基づき1,006ケースを追加し、既存分と合わせて3,978編集ケースを実行した。
- 編集ケース本体と集計テストを合わせた3,981テストは初回実行ですべて成功した。
- Undo／RedoはCodeMirrorの履歴拡張と状態コマンドをUIなしで実行した。
- 質問事項への回答が得られるまでは本書の暫定想定を期待値の根拠とする。
