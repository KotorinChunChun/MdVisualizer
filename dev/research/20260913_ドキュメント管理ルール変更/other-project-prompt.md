# 他プロジェクトへ依頼するプロンプト

以下を対象プロジェクトのタスクへ貼り付けてください。

---

このプロジェクトの開発資料と生成処理を、更新済みのグローバルルールに合わせて整理してください。計画だけで止めず、移動・参照修正・生成スクリプト修正・検証まで実施してください。

配置は次の方針に統一します。

- 版に属する要求・実装計画・設計検討・進捗・テスト結果・リリース結果は、過去・進行中・未来を問わず、最初からdev/history/vX.Y.Z/に置く。要求・実装報告・進捗の名前は既存の版別命名を維持する。
- 次版へ進むときは新しい版フォルダーを作るだけとし、完了後に旧版を移す運用は廃止する。
- 版に属さない調査・検討はdev/research/の対象別フォルダーへ置く。researchにログ用フォルダーは設けない。
- テスト動画・生ログ・録画台帳・実行時の生成結果は対象版のlogs/配下に実行ごとにまとめる。*.logと/dev/history/*/logs/はGit対象外とし、必要な結果の要約は追跡対象の版別報告へ残す。
- dev直下のファイルは継続的なルールと目録のみ。docsは現行の仕様・操作・再現可能な手順を扱う。
- 生成スクリプトも対象版を明示して保存先を決める。dev直下や独立したtest-videosへの固定出力をなくす。録画スキルには--versionを渡し、開始・停止・状態確認・reviewで同じ版を使用する。

最初にグローバルAGENTS、共通PROJECT_RULE、プロジェクトAGENTSと関連skill、Git状態、既存の出力スクリプトを確認してください。古いローカルルールに直下作成や完了後移動が残っていれば、今回の指示に合わせて単純化してください。グローバルルール自体を再変更する必要はありません。

対象版はユーザー指示と要求・作業記録から判断し、製品manifest版だけで決めないでください。版を特定できない資料・ログは推測で割り振らず、その対象だけ確認し、独立して進められる整理は続けてください。

移動対応表を作り、Markdownリンク、画像やHTMLの相対参照、コード内パス、npm等の入口、生成先、目録、プロジェクトskillを同じ変更で修正してください。版別の提案と現行仕様が混在する文書は、原文と判断・未確認事項を保持して整理してください。単に同名という理由で統合・削除しないでください。

既存の未コミット変更、提供原本、未保存文書、秘密情報を保護してください。privateや通常検索対象外の資料は勝手に読まないでください。録画中の台帳・動画を移動せず、既存証跡を自動削除しないでください。ログのGit除外と実ファイル削除は別です。移動後も必要な台帳パスと録画済み判定を保ってください。

検証では移動前後の内容、リンク切れ、旧出力先への再生成、版の誤指定、出力先の逸脱、Git除外を確認してください。生成処理の変更は対象処理で検証し、文書整理だけを理由に製品全体のビルドやGUIを再実行しないでください。署名・インストール・外部公開はこの依頼に含めません。

プロジェクトのコミット方針に従い、検証済みの対象差分だけを日本語でコミットしてください。最後に移動・修正した内容、検証結果、残件、コミットを報告してください。
