# v0.0.17 要求定義

> 他バージョンの実装中は本書を読まず、要求を取り込まないこと。

状態: 実装承認済み。段階実装・検証中。公開は対象外。

## 確定要求

### R1 コードブロックのボタン統一

- draw.ioのコピーと「…」メニューを含め、すべてのコードブロック右上のボタンのデザインを揃える。

### R2 Codex変更採用画面

- 変更前コードを左、変更後コードを右に置いた二分割Diff表示にする。
- 変更前・変更後それぞれの右上に、そのコードをコピーするボタンを設ける。
- 行単位で採用・不採用を選択できるようにする。
- 変更後のコードを利用者が直接編集し、差分を確認しながら微調整して採用できるようにする。

### R3 図・画像の変更比較

- Mermaid、draw.io、SVG、PNGなど、アプリで扱う図・画像全般で変更前・変更後のプレビューを確認できるようにする。
- 基本配置は左上に変更前コード、右上に変更後コード、左下に変更前プレビュー、右下に変更後プレビューとする。
- 図の比較を重視し、コード差分領域は初期状態では折りたたんで非表示とする。必要に応じて展開できるようにする。
- PNGなどコードが存在しない画像は画像プレビューのみとする。
- 変更前・変更後の左右配置と上下配置を切り替えられるようにする。
- 左右分割・上下分割とも、初期比率を50%：50%とする。

### R4 Codexミニパネルの編集範囲

- 行指定がある場合の既定は「指定場所のみ」とする。
- 一行も指定していない場合の既定は「全体」とする。

### R5 右クリックメニュー統合

- 通常テキストの右クリックメニューにも「Codexに相談」「Codexに修正を依頼」を設ける。
- 一行選択時と連続する複数行選択時のメニューを統合し、いずれも相談・修正依頼を利用できるようにする。
- 相談は質問するモード、修正依頼は選択範囲の編集を許可するモードに切り替える。
- 離れた箇所の同時選択は今回の要求に含まない。
- 「Codexに図を依頼」を「Codexに図の編集を依頼」に変更する。

### R6 差分ボタン配置

- メニューバーの「差分」ボタンを「画面」グループの「閲覧のみ」ボタンの右へ、少し余白を空けて移動する。

### R7 図・画像の解説と文字起こし

- PNGなどの画像の解説・文字起こし操作は、画像の右クリックメニューに置く。これらの常設ボタンは画面に置かない。
- SVG、draw.io、Mermaidには画像の解説を用意するが、既定メニューに通常・表の文字起こしは設けない（後続指示による変更）。
- メニューを「Codexで画像を解説」「画像から文字起こし」「Codexで文字起こし（表）」の三つに分ける。
- 解説・文字起こしでは可視化後の画像をCodexに渡し、図のコードから推測するのではなく画像を読み取らせる。
- 通常の文字起こしは文章全文の抽出を重視し、文章として返す。表に見える部分はTSVなどで返してよい。表構造の再現精度を特別に強化する要求は設けない。
- 文字起こし（表）は表に見える部分の構造を正確に再現することを重視し、出力をMarkdownテーブルに限定する。
- 解説、通常の文字起こし、表の文字起こしに、それぞれの目的を明記したプロンプトを用意する。

### R8 図の見た目改善と任意指示による画像編集

- draw.io、SVG、Mermaidのメニューに、見た目の改善を依頼する操作を追加する。
- 可視化後の画像と元コードを両方Codexへ送り、見た目の改善を依頼するプロンプトを付ける。
- 修正案は既存の採用確認画面へ渡す。R2・R3の比較・編集機能と接続し、利用者が確認してから採用する。
- PNGの右クリックでも図・画像の編集を依頼できるようにする。利用者が任意のプロンプトを入力し、その指示に従う編集を依頼する。見た目改善だけには限定しない。
- PNGは元コードがなくても編集対象とし、変更前後の画像を採用確認画面に表示する。
- Mermaid、draw.io、SVGの今回の画像向け既定操作は解説と見た目改善とする。R5の既存の図編集依頼入口の名称変更は維持する。

### R9 プロンプトのスキル管理とメニュー生成

- Codexへ送るプロンプトをスキルとしてまとめ、今回指定した操作のプロンプトを本システムの既定スキルとして用意する。
- テキスト、コードブロック、可視化後の画像などの対象属性をスキル側で定義する。
- 対象属性と利用者の表示設定に応じて、右クリックメニューまたはコードブロック右上のメニュー項目を生成する。
- 設定画面に所定フォルダーのスキル一覧を表示し、スキルごと・対象データごとにメニューへ表示するかどうかを選べるようにする。
- 決まったフォーマットのスキルファイルを追加・削除できるようにする。
- 設定画面でシステムが採用するプロンプトを確認・修正できるようにする。
- プロンプトはファイルとして利用者が後から編集できるようにする。
- Claudeが定める形式に準ずるスキルファイルを採用する。JSONファイルへの書き出し要求は取り消す。

### R10 テキストエディターのSVG追加とツールバー折り返し

- テキストエディターのツールバーにSVGを追加するボタンを設ける。
- コマンドが横幅に収まらない場合、ツールボタンを二段・三段へ折り返して表示できるようにする。

### R11 Codex会話パネルの整理

- 選択テキストを対象とする会話・質問と、添付画像または可視化後の画像を対象とする会話・質問を分かりやすく扱う。
- この会話パネルの回答はテキストを前提とする。R8の画像編集・採用確認の要求は維持する。
- 既存のテキスト取り込みと画像追加が混在して分かりにくい状態を改善する。
- 対象テキスト、画像、質問入力、回答のレイアウトと表示順を見直す。
- 対象テキスト、添付画像、質問入力、会話履歴の消去タイミングを整理する。具体的な自動消去条件は未確定とする。

### R12 会話の継続・新規開始と履歴再開

- テキスト・画像を取り込む際、「現在の会話に追加」と「新しい会話を開始」を選べるようにする。
- 過去の会話を一定期間保持し、現在の会話と過去の会話を切り替えて再開できるようにする。既存ログの利用可否は調査する。
- 会話一覧に最終会話日時を表示し、最後にいつ会話したか分かるようにする。
- 最終会話から1時間以内は緑、1時間超は赤で示す。
- 古い会話で相談を再開する際、キャッシュが使われない場合の負担を知らせる注意書きを設ける。キャッシュ切れの断定可否と文言は実際の接続仕様を調査して確定する。
- 会話一覧に会話文字数とコンテキスト量を併記する。会話本文の文字数、現在のコンテキスト量、累積使用トークンは区別し、取得できない値を実測値として表示しない。
- 会話履歴を開き、利用者が任意の会話を選択して切り替えられるようにする。「ログ」ボタンは「会話履歴」への名称変更を案とする。
- 会話履歴から、その会話に添付した画像を確認できるようにする。
- 添付画像に「画像1」などの識別表示を付け、どの発言で追加した画像か分かるようにする。送信プロンプトにも画像の識別表示を含め、会話と画像の対応を分かるようにする。

## 質問と回答

- 2026-09-13: 図の比較対象はMermaidとdraw.ioだけか。
  - 回答: SVG、PNGなどの画像も含めてすべて対象。PNGなどコードがない画像はプレビューのみ。
- 2026-09-13: 分割初期比率の適用範囲。
  - 回答: 上下・左右とも50%：50%。
- 2026-09-13: 複数範囲とは離れた箇所の同時選択も含むか。
  - 回答: 連続した複数行を意味する。離れた箇所は含まない。

- 2026-09-13: JSONとClaude準拠スキルファイルの関係。
  - 回答: JSONの要望を取り消し、スキルファイルを採用する。
- 2026-09-13: 文字起こし（表）の出力形式。
  - 回答: Markdownテーブルとする。
- 2026-09-13: コード差分の初期表示。
  - 回答: 初期状態では折りたたむ。
- 2026-09-13: 画像種別ごとの操作とスキルの表示設定を修正。
  - PNGは任意のプロンプトによる編集を残す。Mermaid、draw.io、SVGの画像向け操作は解説と見た目改善とし、文字起こしは不要。
  - 設定画面に所定フォルダーのスキル一覧と対象データごとのメニュー表示設定を設ける。

- 2026-09-13: 対象変更時に会話を継続するか、新規開始するか。
  - 回答: 両方を選択可能にする。過去の会話の再開、最終会話時刻、1時間を境とする色分け、文字数・コンテキスト量、古い会話再開時の注意表示も追加する。

## 実装開始時の回答（2026-09-13）

- Luna・Terraのサブエージェントを活用し、順次実装する。
- PNGの変更画像取得は一度試し、実現困難なら将来実装として保留してよい。
- PNG編集を実装する場合、外部画像の採用時は「上書き」「別名保存して参照差し替え」「旧画像をアーカイブへ移して元の名前で保存」の三択を設ける。
- Diffで変更後コードを編集したら即座にプレビューを更新する。意図的な構文破壊、修正、正常な変更のテストを行う。
- スキルは近いファイル形式とプロンプト管理が目的。Claude固有のコマンド実行やサブエージェント機能の再現は不要。
- SVG追加はSVGコードブロックのひな形挿入とする。円と「SVGサンプル」程度の簡単な表示例を含める。
- 会話履歴の既定保持期間は30日で設定変更可能。未送信入力・添付も保存し復元する。
- 0日は履歴保存を停止して既存履歴も消す。保持期間短縮時には期限切れ分を即時削除する。
- 会話履歴への改名、画像番号と添付時点の紐付け、1時間を目安とした注意表示を採用する。キャッシュ切れとは断定しない。
